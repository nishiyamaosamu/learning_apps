# パターン別の詳細ガイド

すべての記述例は `src/videos/demo/demo.tsx` にある。ここでは間違えやすい点だけ補足する。

## title（タイトルカード）

```ts
{
  pattern: "title",
  series: "ITパスポート講座",          // シリーズ名（講座名）
  title: "企業は何のために\n活動するのか", // \n で2行。1行13文字まで
  keywords: ["経営資源", "企業理念", "CSR"], // 本編で扱う語を3つまで。目立たせない前提の飾り
}
```

- keywords は「本編に出てくる用語の予告」。文にしない、体言止めの単語だけ。

## bullets（箇条書き＋イラスト）

- `marker: "blue"` は覚えてほしい用語に。`"pink"` は動画内で1〜2回だけの最強調。
- `sub` は text の補足説明。text と同じ内容を繰り返さない。
- `illust` は `public/images/<app>/` に実在するファイルのみ（例 `images/ipa_ip/scene-xxx.png`）。`ls public/images/<app>/` で確認してから。
  無ければ省略してよい（箇条書きだけで成立するレイアウトになる）。

## vs（対比）

- **左右の rows は同じ観点（k）を同じ順で並べる**。観点が揃わないと対比にならない。
- 最後の行は「弱点」vs「強み」のように結論の差がつく観点にすると締まる。
- 列タイトルのアイコン（left.icon / right.icon）は省略可。付けるなら両方に付ける。

## flow（ステップフロー）

- `abc` はステップの頭文字や番号（"P" や "1"）。`name` は日本語2〜4文字。
- ハイライトは自動で左から順に移動する。データでの指定は不要。
- 5ステップを超えるなら flow を2シーンに分けるか、layers を検討する。

## matrix（2×2マトリクス）

- `cells` は [左上, 右上, 左下, 右下] の順。
- `tone: "hi"`（primary100）は最重要の1象限、`"lo"`（primary50）は次点。
  tone を付けた象限だけ、説明の流れに合わせて自動で順に点灯する。全部には付けない。
- colLabels が横軸（上）、rowLabels が縦軸（左）。

## layers（階層図）

- 配列は**上の層から**書く（OSIなら 7→1）。積み上げアニメは自動で下から始まる。
- `highlight: true` は「今日の主役」の1層だけ。note と合わせて使うと効果的。
- 階層に順序の意味がないなら bullets を使う。

## graph（計算・グラフ）— 座標系に注意

viewBox は 220×150。**y は下向きが正**（上が小さい値）。軸は自動で描かれる:
- 原点 = (18, 138)、x軸の右端 = 214、y軸の上端 = 8
- 線は x: 18〜208 / y: 18〜138 の範囲に収める

```ts
lines: [
  // role: "guide" = 破線の補助線 / "sub" = 灰色の副系列 / "main" = 青の主系列（最後に描画される）
  { x1: 18, y1: 96, x2: 208, y2: 96, role: "guide", label: "固定費", labelX: 24, labelY: 90 },
  { x1: 18, y1: 96, x2: 205, y2: 56, role: "sub",  label: "総費用", labelX: 172, labelY: 50 },
  { x1: 18, y1: 138, x2: 205, y2: 18, role: "main", label: "売上高", labelX: 170, labelY: 14 },
],
point: { x: 112, y: 78, label: "損益分岐点", labelX: 86, labelY: 66 }, // 交点＝注目点（ピンク）
```

- **point は実際に線が交わる座標に置く**。2直線の交点は手計算で求める
  （線分 (x1,y1)-(x2,y2) をパラメータ表示して連立。ずれると静止画確認で一目で分かる）。
- label の位置は線の右端付近・線と重ならない側に。
- 右側の式カード: `formula` は `\n` 改行で2行まで。`noteHighlight` が結論
  （ピンクマーカーになる）、`noteRest` は補足（「。〜」で始める）。

## term（用語ドン）

- 1動画に1〜2回まで。連発すると効かなくなる。
- `sub` は「正式名称 — 一言定義」の形（例: "Domain Name System — ドメイン名とIPアドレスを対応づけるしくみ"）。
- **`chip` は分類ラベル**。その語が*何の一種か*を4〜10文字で書く（迷惑メール→「メールの脅威」、
  ファイルレス→「マルウェアの一種」、ダークウェブ→「攻撃者の市場」、DNS→「名前解決のしくみ」）。
  重要度・順位を主張する言葉（「今日のキーワード」「重要用語」「必修」など）は入れない——
  1本に1〜2回出るページで「今日の」と言うと矛盾し、既知の語（迷惑メールなど）では大げさに響く。
  「今日のキーワード」はタイトルカードのゴーストチップ（予告）→ まとめ②キーワード回収 の呼応に
  予約された言い回しなので、本編⑦で先に使うと締めの回収が濁る。
- 分類が自然に言えないときは `chip` を省略する（アイコン＋大見出し＋定義だけの辞書型になる）。
  ラベルをひねり出すより省略のほうがよい。
- **置いてよいのは「新出の専門用語」だけ**（ファイルレス・ダークウェブ・シャドーIT のように、
  受講者がこの回で初めて名前を知る語）。**迷惑メール・パスワードのような一般に知られた語を
  用語ドンで大写しにしない** — 語を額縁に入れる形そのものが「これは新しく難しい言葉だ」と
  主張するので、既知の語では扱いの温度感がずれる（2026-07-30 に L3 s06 で差し戻し）。
  既知の語のページは、その語の**中身**を見せる形にする（例: 迷惑メール＝受信メール1通のモックを
  出して危ない箇所を語りに合わせて指す。実装は `sg-L3-human-deception.tsx` の `SpamMailScene`）。
- 絵は最初の1.5秒で完成してあとは動かないので、4文の語り（＝20秒級）を受けると
  「止まった絵に声だけ」の時間が長い。**それを密なページの後の息継ぎとして意図しているなら可**。
  逆に、語りが段階を追って情報を足していく内容（届く→ここが危ない→装っている→こうなる）なら、
  段階的に出せる custom のほうが尺を持たせられる。

## binary（計算ステップ）

- 2進数以外にも使える（16進数、桁の重みで分解できる計算全般）。
- `weight` の上付き数字は Unicode: ⁰¹²³⁴⁵⁶⁷⁸⁹（例: "2³＝8"）。`<sup>` は使えない。
- digit "0" の桁は自動で減光され、product も灰色になる。データは正直に "0" を書く。

## quiz（動画内クイズ）

- 本編で説明した内容だけから出題する（新情報を出さない）。
- `correct: true` は必ず1つ。

### 設問文の作り方（question と問いのセグメント）

- **設問文は、それ単体で「何について問われているか」が分かる文にする。主語を落とさない。**
  直前のページを見ていた前提で「すぐ当てられないとき決めるのは？」と書くと、
  何がすぐ当てられないのかが読み取れない（sg-L37 v1 が差し戻され、
  「**パッチが**すぐ当てられないとき決めるのは？」に直した）。書いたら**前のページを
  隠して読み直す**チェックをする — 指示語・省略された主語（それ・この場合・すぐ〜ないとき）が
  残っていたら、本編で使った用語をそのまま主語として入れる。
- 主語を落としてはいけない理由は、**問いを読み上げている間、画面の `question` が唯一の文字だから**。
  `QuizSlide` の字幕帯（foot）は `revealAtSec + 0.8` から出る＝**正解発表まで字幕が出ない**
  （考える間に正解の手がかりを字幕で先出ししないための仕様）。他のページと違い、
  「字幕が補ってくれる」が成り立たない。
- そのぶん `question` は20字上限がきつい。主語を足して溢れるときは、**主語を削るのではなく
  述部を詰める**（「決めておくのは」→「決めるのは」など）。
- 読み上げ側（問いのセグメント）も同じ主語を入れて画面と揃える。こちらは字幕帯の
  1行上限（全角30字）に収める必要があるので、主語を足した結果31字を超えたら
  語尾を詰める（「〜先に決めておくのはどちらでしょうか。」→「〜先に決めるのはどちらですか。」）。
  1本の中で語尾（でしょうか／ですか）が揃わなくなっても、**主語が入っている方を優先する**。
- **正解の位置は問ごとに散らす（1本の動画で全問Aは禁止）**。2択なので放っておくと
  全部Aになりがち。書き終えたら A/B の並びを見て、片方に寄っていたら選択肢の
  text を入れ替える（`key` は上から "A"/"B" のまま固定。入れ替えるのは text と
  `correct: true` の位置だけ）。目安の配置:
  - 2問 → `A, B` / `B, A`
  - 3問 → `A, B, A` / `B, A, B` / `A, B, B` など、AとBを必ず両方使う
  ナレーションは正解を文言で言う（「正解は、〜です」）ので、選択肢の順番を入れ替えても
  音声・字幕・`revealAtSec` はそのままでよい。
- 正解位置を入れ替えるので、**ダミー選択肢も本編に出た用語で「ありそう」に**する
  （明らかに捨て札の選択肢だと、Bが正解の回だけ不自然に浮く）。
- `foot` は省略すると標準文言。特に書くことがなければ省略でよい。
- `node scripts/lint-videos.mjs` が「全問Aが正解」を検出して落とす。

## 尺の調整

各パターンの尺は内容量から自動計算される（`src/videos/duration.ts`）。
基本は指定不要。ナレーションを想定して特定シーンを長くしたいときだけ
`durationSec` を明示する（アニメーションは先頭から同じタイミングで走る）。
