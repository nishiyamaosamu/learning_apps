# ナレーション音声パイプラインの詳細

仕組みの要点: **字幕1枚 = 1文 = 1音声ファイル(mp3)**。各mp3の実測秒数（ffprobeで採る）を
そのまま字幕の切り替えタイミングとシーン尺に使うので、タイムスタンプ推定なしで完全同期する。
完動する最小手本は `src/videos/demo/narration-demo.tsx`。

## ファイル命名と置き場所

```
content_works/video/
├── narration/<app>/<id>.md          # シナリオ（ページ表 + 原稿）。人が読み返す用
├── narration/<app>/<id>.jobs.json   # TTSジョブ（ファイル名 → 読み上げテキスト）
├── public/audio/<app>/<id>/         # 生成されたmp3
└── src/videos/<app>/<id>.audio.json # 実測秒数（audio-durations.mjs が生成）
```

- セグメントのファイル名は `s{シーン番号2桁}-{通し番号}.mp3`（例 `s03-2.mp3` = 3ページ目の2文目）。
  シーン番号は scenes 配列の 1 始まり。番号が揃っていると再生成・照合が迷わない
- jobs.json はフラットな辞書。テキストは**字幕に出す文とまったく同じ**にする（違うと口と字幕がズレて見える）

### 完成した動画の途中にページを追加するとき（番号の付け替え）

シーン番号は scenes 配列の位置なので、**途中に1ページ挿入すると以降の全ページの番号がずれる**。
新ページだけ `s08b-*` のような枝番で逃げず、**以降の音声ファイルを降順で改名して番号を詰め直す**
（枝番を許すと「シーン番号2桁＝配列位置」という唯一の手がかりが崩れ、次に直す人が
どの音声がどのページか分からなくなる）。音声の中身は変わらないので**再生成は不要**:

```bash
cd content_works/video/public/audio/<app>/<id>
# 後ろから順に +1（昇順でやると既存ファイルを踏む）。共通音声だけのページ番号は空き番になる
for old in 13 12 11 10; do new=$((old+1))
  for f in s${old}-*.mp3; do mv "$f" "s${new}-${f#s${old}-}"; done; done
cd ../../../.. && node scripts/audio-durations.mjs <id>   # audio.json を作り直す
```

同じ付け替えを `narration/<app>/<id>.jobs.json`・`narration/<app>/<id>.md` の見出し・
`.tsx` の `N("sNN-n.mp3", …)` にも通す（4か所ずれると N() が「秒数がありません」で即落ちるので
取りこぼしは検出できる）。新ページの音声だけを一時 jobs で生成する手順は下記「一部だけ再生成する」と同じ。

### 例外: 難読語の読みを直したいとき（音声と字幕を分ける）

`tts.py` に読み仮名の指定機能はない。「平文（ひらぶん）」のように TTS が誤読する語は、
**音声用テキストだけ仮名書きにし、字幕は漢字表記のまま**にする。`N(file, text)` の `text` は
**字幕にしか使われず**、音声は `file` の mp3 そのものなので、両者が食い違っても再生には影響しない。

| | 書くもの |
|---|---|
| `narration/<app>/<id>.jobs.json`（音声） | `"ひらぶんを暗号文に変えることが暗号化、…"` |
| `src/videos/<app>/<id>.tsx` の `N()`（字幕） | `"平文（ひらぶん）を暗号文に変えることが暗号化、…"` |

読みを添えるのは**初出の1回だけ**にする（毎回添えると字幕がうるさい）。この分岐は必ず
`.tsx` のコメントと `narration/<app>/<id>.md` に理由を残す — 後から「音声と原稿が違う」と
誤解して直されないようにする。既定はあくまで「まったく同じ」で、これは誤読語だけの例外。

**同じ語が複数セグメントに出るときは、全部を仮名書きに揃える。** Gemini TTS は同じ漢字を
ファイルごとに違う読みで返すことがあり（sg-L4 の「宿主」は s04-2/s05-2 が「やどぬし」、
s10-2 だけ「しゅくしゅ」になった）、聞いている側には用語がブレて聞こえる。誤読が1ファイルでも
見つかったら、その語を含む**全ファイル**を仮名書きにして再生成する — 1ファイルだけ直すと、
残りは漢字のまま＝あとでフル再生成したときに揺れが戻る。

**直す前に必ず grep で全セグメントを洗う（1本ずつ直すと取りこぼす）。** 人の指摘は
「気づいた1文」しか挙がらないが、同じ語はたいてい他のページにも散っている
（sg-L38 の指摘は s06-2 の「通します」だけだったが、実際は s04-1・s05-2・s15-1 にも
「通ります」「通すか」があった）。指摘された語の**漢字1字**で jobs.json と `.tsx` の両方を
引き、活用形ごと拾ってからまとめて直す:

```bash
cd content_works/video
grep -n "通" narration/<app>/<id>.jobs.json src/videos/<app>/<id>.tsx
```

活用語尾（す／します／ります／し／った…）で grep すると変化形を落とすので、
**語幹の漢字だけ**で引くこと。ヒットの中から誤読しうる読みのものだけを選ぶ。

**とくに危ないのは「訓読みの和語が音読みされる型」**（宿主＝しゅくしゅ、内部犯＝ないぶほん、
通す＝つうす）。同じ漢字が音読みの熟語としても頻出する回では、その熟語に引きずられて
訓読み側が音読みになる — sg-L38 は「通信」が20文以上に出る回で、「通します」が
「つうします」になった。**回のキーワードに含まれる漢字が、和語動詞としても原稿に出てくる場合は、
誤読を確認するまでもなく最初から和語側を仮名書きにする**（熟語側は正しく読まれるので触らない）。

**誤読が確認済みの語**（新しい原稿でこの語を使うときは、最初から音声側を仮名書きにする）:

| 語（字幕表記） | 音声用テキスト | 誤読 |
|---|---|---|
| 平文 | ひらぶん | へいぶん |
| 宿主 | やどぬし | しゅくしゅ |
| 内部犯 | ないぶはん | ないぶほん |
| 通す（通します／通ります／通すか） | とおす（とおします／とおります／とおすか） | つうします（「通信」に引きずられる。sg-L38 v1 で差し戻し。熟語の「通信」「交通」は正しいので直さない） |
| DoS | ドス | ディーオーエス |
| DDoS | ディードス | ディーディーオーエス |
| JIS Q 31000 | ジス キュー さんまんいっせん | さんまんいちまん |
| JIS Q 27001 | ジス キュー にまんななせんいち | 桁の切り方が回・ファイルごとに揺れる |
| JIS Q 27002 | ジス キュー にまんななせんに | 同上 |
| JIS Q 27014 | ジス キュー にまんななせんじゅうよん | 同上 |
| 対になる（対の） | ついになる（ついの） | たいになる |
| WORM機能 | ダブリュー オー アール エム 機能 | 「ワーム」と読むとマルウェアのワームと衝突（sg-L35 v1 で差し戻し） |

誤読を新しく見つけたらこの表に足す（次の動画で同じ間違いをしないための共有辞書）。

「対」は**熟語の一部なら直さなくてよい**（「反対に」「対策」「対比」は正しく読まれる）。
仮名にするのは**「対になる」「対の」のように単独で『つい』と読ませたいとき**だけ。

**読み上げる数字は、例外なく音声側を仮名書きにする。** 対象は規格番号（JIS Q 27001 /
ISO/IEC 27002 / JIS Q 15001）、法令の条番号、規格世代の数字（WPA2・WPA3 など）を含む
**「原稿の中で声に出して読まれる数字すべて」**。Gemini TTS は桁の区切りを取り違えるうえ
（`31000` を「さんまんいちまん」と読んだ。sg-L22 で差し戻し）、**同じ数字でもファイルごとに
違う切り方で読む**ため、放っておくと1本の中で読みが揺れる（sg-L29・sg-L28 で差し戻し）。
音声用テキストだけ「ジス キュー さんまんいっせん」「ジス キュー にまんななせんいち」のように
**読み方をそのまま書く**（字幕・画面は数字表記のまま。数字は字幕を見れば読めるので、
略語と違って**字幕に読みを添えない**）。位取り読み（にまんななせんいち）にするか
桁読み（に なな ぜろ ぜろ いち）にするかは、その規格が実際にどう呼ばれているかに合わせる。

**仮名書きにするときは、読み上げる語のまとまり全体を仮名にする。** 数字だけを仮名にして
隣のラテン文字（略語・記号）をそのまま残すと、1文の中でラテン文字と仮名が混在し、
その継ぎ目で読みが不自然になる — `JIS Q にまんななせんいち` が実際に差し戻された
（sg-L28 v2。`ジス キュー にまんななせんいち` に直して解消）。規格名なら記号部（`JIS Q` /
`ISO/IEC`）まで、製品名やバージョンなら語頭から、**声に出して1つの名前として読まれる範囲を
まるごと**仮名に置き換える。

**仮名書きにした数字の後ろには必ず半角スペースを入れる。** 仮名の数字と次の語が地続きだと、
どこで数字が終わるか音の上で分からず不自然に聞こえる — `にまんななせんいちという規格に` が
実際に差し戻された（sg-L28。`にまんななせんいち という規格に` で解消）。前側も同様に、
`ジス キュー にまんななせんいち` のように分かち書きで語の切れ目を作る。**数字を読み上げる回
すべてに効く規則**なので、仮名書きにしたら前後の区切りまでセットで確認する。

なお**同じテキストのまま引き直すだけでは直らない**（生成のたびに揺れるので同じ不自然さが
再発する）。必ずテキストを変えてから再生成する。

**「別の回で正しく読まれた」を数字のまま渡す根拠にしてはいけない。** sg-L29 は
「27001 は L28 で正しく読まれたので数字のままでよい」と判断して差し戻された。
TTS の出力は生成のたびに変わるので、**過去に正しく読めたことは次も読める保証にならない**。
数字を含む語は、確認するまでもなく最初から仮名書きにする（仮名書きにして損はない）。

数字の直後に助詞「は」が来る文（`27002は…`）は、仮名書きにすると
「にまんななせんには」と平仮名が続いて切れ目が見えなくなる。文はそのままで問題なく
読まれるが、**生成後に一度聞いて確認する**（言い方が変なら下の「言い換えて再生成」に従い、
字幕と `.md` も同じ文に直す）。

**読みは合っているのに「言い方が変」なときは、文そのものを言い換えて再生成する。**
同じテキストで作り直しても抑揚はほぼ再現されるので直らない。とくに
「最後に、〈カタカナ語〉という考え方です。」のように読点の直後にカタカナ語が来る形は、
区切りが不自然に聞こえやすい（sg-L22 の「最後に、サイバーハイジーン…」で指摘。
「最後に紹介するのは、サイバーハイジーンという考え方です。」に変えて解消）。
読点とカタカナ語の間に語を足して、文節を長くするのが効く。
文を変えたら `.tsx` の `N()` の字幕・`narration/<app>/<id>.md` も同じ文に直す。

**略語は「アルファベットを1字ずつ読む」と決めつけない。** 定着した読み方がある略語は、
そちらでないと視聴者の耳に馴染まない（DoS は「ドス」、DDoS は「ディードス」。
「ディーオーエス」と読んだ sg-L12 v1 が差し戻された）。1字ずつ読むのが正しい略語
（APT＝エーピーティー など）と混在するので、**略語を初めて使う回では読み方を確認してから
音声を作る**。読み方が定着している略語は、字幕にも初出の1回だけ読みを添える
（例: `"まずは、DoS（ドス）攻撃です。"`）— 音声だけ仮名書きにすると、画面から読み方が学べない。
逆に**1字ずつ読む略語には字幕の読み添えを付けない**（字幕を見れば読める。EDR・MDM・UTM・DLP は
sg-L39 でこの扱い）。

**略語をカタカナ読みさせる前に「その読みが別の一般語と衝突しないか」を確かめる。**
カタカナに開くと、同じ音の普通名詞・別の用語と区別がつかなくなることがある —
WORM（Write Once Read Many）を「ワーム」と読ませた sg-L35 v1 が差し戻された
（自己増殖するマルウェアの「ワーム」と同音）。**衝突する読みは、区別の一文を足して
救おうとしない**（v1 は「マルウェアのワームとは別のものです」と添えたが、
そもそも同じ呼び方をしなければ要らない一文だった）。**1字ずつ読みに変え、
実務での呼ばれ方をそのまま言い方にする**のが正しい直し方
（WORM は `ダブリュー オー アール エム 機能` と読み、原稿でも「WORM機能と略される」と言う）。
元の英語を教えたいときは、ナレーションで綴りを読み上げるのではなく
**画面に元のつづりを出し、その説明文の読み上げに `segStart` で同期させる**
（sg-L35 s10 は `Write Once Read Many` を「書き込みは一度、読み出しは何度でも、
という意味の略です」に合わせて出している）。

```json
{
  "s01-1.mp3": "今回は、企業活動と経営資源について学びます。",
  "s02-1.mp3": "企業活動の目的は、社会に価値を提供することです。",
  "s02-2.mp3": "利益は、その活動を続けるための条件になります。"
}
```

## 音声生成 → 実測

```bash
cd content_works/scripts
mise exec -- uv run tts.py --jobs ../video/narration/<app>/<id>.jobs.json \
    --out-dir ../video/public/audio/<app>/<id>

cd ../video
node scripts/audio-durations.mjs <id>    # → src/videos/<app>/<id>.audio.json + 合計秒数の報告
```

- 声は tts.py の既定（Zephyr / gemini-3.1-flash-tts-preview / ja-JP）をそのまま使う。全動画で声を揃える
- 生成は1ファイル数秒〜数十秒。**全ファイル生成が終わってから** audio-durations を実行する
- audio-durations が「⚠ 359秒超の恐れ」を出したら、原稿を削って**該当ファイルだけ**再生成する（下記）

### 一部だけ再生成する

原稿を直した・読みが不自然だったファイルだけ作り直せばよい。該当キーだけの一時 jobs を作って回す:

```bash
cd content_works/scripts
echo '{"s05-2.mp3": "直した読み上げテキスト。"}' > /tmp/patch.jobs.json
mise exec -- uv run tts.py --jobs /tmp/patch.jobs.json --out-dir ../video/public/audio/<app>/<id>
cd ../video && node scripts/audio-durations.mjs <id>   # 秒数が変わるので必ず採り直す
```

narration/<app>/<id>.jobs.json 本体も同じ文に直しておく（原稿と音声の対応が真実であり続けるように）。

## 実装パターン

### 共通: loader を1回作る

```tsx
import { narrationLoader } from "../../parts/narration";
import durations from "./<id>.audio.json";   // audio-durations.mjs が作る（先に音声工程を済ませる）

const N = narrationLoader(durations, "audio/<app>/<id>");
```

`.audio.json` にキーが無いと N() が即エラーを投げる。「音声を作り忘れたまま無音で完成」を防ぐための仕様。

### 既製パターンのシーン

spec に narration を書くだけ。telop は書かない（字幕が音声から出る）。

```tsx
{
  pattern: "bullets",
  heading: "企業活動の目的",
  icon: "corporate_fare",
  bullets: [{ text: "社会に価値を提供する", marker: "blue" }],
  narration: [
    N("s02-1.mp3", "企業活動の目的は、社会に価値を提供することです。"),
    N("s02-2.mp3", "利益は、その活動を続けるための条件になります。"),
  ],
}
```

### カスタムシーン

セグメント配列を定数にして、**spec と SlideShell の両方に同じものを渡す**。
spec 側が音声とシーン尺、SlideShell 側が字幕表示を担う（片方だけだと音が出ない/字幕が出ない）。

```tsx
const SEG5 = [N("s05-1.mp3", "…"), N("s05-2.mp3", "…")];

const MyScene: React.FC = () => (
  <SlideShell heading="…" narration={SEG5}>…</SlideShell>
);

// spec:
{ pattern: "custom", name: "my-scene", durationSec: 4, narration: SEG5, component: MyScene }
```

- `durationSec` は「アニメーションの最低尺」。ナレーションの方が長ければ自動で伸びる
- 音声はレンダラーが spec.narration から自動で鳴らす。**シーン内に `<Audio>` を手動で置かない**（二重再生になる）

### title・ダーク幕間（SlideShell が無いシーン）

音声は spec.narration で鳴る。字幕は出ないので、
- title: 挨拶の1文だけにする（画面のタイトル文字が実質の字幕）
- ダーク幕間: 画面中央の大きな文字を読み上げ文と一致させる（それ自体が字幕）

### 考える間・タメ（gapBeforeSec）

セグメントの読み上げ前に無音の間を置ける。間の間、字幕は前のセグメントのまま残る
（正解などを先出ししない）。シーン尺・音声・字幕すべてに自動で反映される。

```tsx
N("s10-3.mp3", "正解は、イの経営資源です。", { gapBeforeSec: 1.8 })
```

使いどころ: クイズの問い→正解の間（1.5〜2秒）が代表。まとめ前の一拍などにも使えるが、
多用すると間延びする。

### quiz のリビール同期（考える間つき）

問いを読み終えたら考える間を置き、正解読み上げと同時にリビールする。
`revealAtSec` は正解セグメントの開始秒 — `segStart(QSEG, i)` で取る（手で足し算しない）:

```tsx
import { narrationLoader, segStart } from "../../parts/narration";

const QSEG = [
  N("s10-1.mp3", "ここで問題です。…"),
  N("s10-2.mp3", "…でしょうか。"),
  N("s10-3.mp3", "正解は、イの経営資源です。", { gapBeforeSec: 1.8 }),
];
{
  pattern: "quiz",
  question: "…",
  choices: [...],
  narration: QSEG,
  revealAtSec: segStart(QSEG, 2), // s10-3 の読み上げ開始（gapBeforeSec 込み）= 正解発表
}
```

### 語りに画面を同期させる（segStart）

カスタムシーンで「N文目に合わせて要素を出す・光らせる」も同じヘルパーで組む。
シーン内の音声はシーン頭から始まるので、`segStart(SEG, i)` がそのまま演出の `delaySec` になる:

```tsx
// 2文目の読み上げ開始と同時に結論カードを出す
const b = useAppear(segStart(SEG5, 1));
```

ナレーションが3文以上あるページは、少なくとも1つの要素を後半のセグメントに同期させて
「語りに画面がついてくる」感を作る（全要素を頭で出し切ると後半が止まった絵になる）。

### オープニングジングル（title で自動再生）

title シーンではレンダラーが `public/audio/common/opening_jingle.mp3`（6.8秒）を自動で鳴らす。
title の尺もジングルに合わせて 7.2 秒が既定。**title にナレーションを付けない**
（ジングルと声が重なる）。導入の語りは2ページ目から始める。

### 共通音声（定型セリフの使い回し）

クイズ導入の幕間と、まとめ最後の締めの一言は**全動画で文言が固定**なので、動画ごとにTTS生成せず
`public/audio/common/` の音声を使い回す。読み・抑揚のブレも無くなる（毎回生成すると同じ文でも
微妙に尺が変わる）。

```
narration/common/common.jobs.json     # 共通セリフのジョブ定義（人が読み返す用）
```

新しい定型セリフ（今後増える共通フレーズ）を足す手順:

1. `narration/common/common.jobs.json` に `{ "新ファイル名.mp3": "テキスト" }` を追記
2. `cd content_works/scripts && mise exec -- uv run tts.py --jobs ../video/narration/common/common.jobs.json --out-dir ../video/public/audio/common`
3. `cd ../video && node scripts/audio-durations.mjs common`（`src/videos/common/common.audio.json` を更新）
4. `src/parts/common-narration.ts` に `export const XXX_SEG = NC("新ファイル名.mp3", "テキスト");` を追加

## 尺の管理（5:59 上限）

- 読み上げ速度は実測でおよそ **4.5〜5字/秒**（Gemini TTS ja / Zephyr）
- 動画尺 ≈ ナレーション合計 + シーン数 × 0.9秒（テール） + gapBeforeSec の合計 + title 7.2秒
- **原稿の総文字数を先に管理する**のが唯一確実な方法: 目標 1,200〜1,400 字（4〜5分）。
  1,500 字を超えたら音声を作る前に削る（作った後に削ると再生成コストがかかる）
- audio-durations.mjs が合計 330 秒超で警告を出す。最終確認はレンダリング後に
  `ffprobe -v error -show_entries format=duration -of csv=p=0 draft/<app>/<出力名>.mp4` で 359 秒以下を見る
  （出力名は app-lesson-version 形式。例 `ip-L1-v1.mp4` — SKILL.md 工程8参照）

## トラブルシュート

| 症状 | 原因と対処 |
|---|---|
| `〜の秒数がありません` エラー | 音声未生成 or audio-durations 未実行。音声工程を先に済ませる |
| 音声が鳴らないシーンがある | spec に narration を渡し忘れ（SlideShell だけに渡している） |
| 字幕が切り替わらない | SlideShell に telop（固定文字列）を渡している。narration に切り替える |
| 同じ声が二重に聞こえる | シーン内に `<Audio>` を手動で置いている。spec.narration に一本化する |
| 尺が原稿から想定した長さと大きく違う | 音声再生成後に audio-durations を採り直していない |
| tts.py が認証エラー | `secrets/` のサービスアカウントJSONが前提。ユーザーに確認する |
| フルレンダリングが delayRender タイムアウトで繰り返し落ちる（`Ms.tsx` の `loadFont` で止まる） | ホストのメモリ不足。**まず `npx remotion render <id> <out>.mp4 --concurrency=3 --timeout=180000` を試す**（並列タブを減らすとフォント読み込みが timeout しない。stills が通るのにフルレンダだけ落ちるときはこれ）。それでも落ちるなら `--frames=0-N` / `--frames=N+1-末尾` の2回に分けてレンダリングし、`ffmpeg -f concat -c copy` で無劣化結合する（結合点のフレームを目視確認） |
| コードを直したのに mp4 に反映されない | webpack バンドルキャッシュが古い。`--bundle-cache=false` を付けて再レンダリングする。修正の再レンダリングでは、直した箇所のフレームを `ffmpeg -ss <秒> -i <mp4> -frames:v 1 check.png` で**mp4 から**抽出して反映を確認してから納品する（stills はソースから作るので証拠にならない） |
