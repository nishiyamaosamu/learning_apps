## この回の位置づけ

第6章（法務）の6本目。L47（知的財産権）・L48（サイバーセキュリティ基本法／不正アクセス禁止法）・
L49・L50（個人情報保護法）・L51（刑法）と同じ章の続きで、**「場面ごとに担当する法律がある」**
という切り口で3つの法律を並べる。

| 場面 | 法律 |
|---|---|
| 電子の署名 | 電子署名法（＋ 認定認証事業者・電子証明書） |
| 広告のメール | 特定電子メール法 |
| ネット上の投稿 | 情報流通プラットフォーム対処法 |

### 隣の回との突合（L47〜L51 の narration を読んで確認済み）

- **罰則の扱いは L47〜L51 と揃える**。「認められません」「義務づけられます」までにとどめ、
  **刑名・年数・金額は出さない**（刑法改正で刑名の呼び方が動いており教材に揺れを持ち込まないため。
  試験で問われるのは「何が義務か・誰に送ってよいか」の側）
- **L51（刑法）とは語も重ねない**。L51 は「電子署名法・特定電子メール法は L52」と明記して
  触れていないので、この回も刑法の罪名には戻らない
- **L49（個人情報保護法）のオプトイン**と用語が重なる。L49 は「先に同意をもらう方式」と定義して
  第三者提供の文脈で使ったので、この回は**再定義せず「以前学んだオプトイン」と受けて**
  広告メールの文脈だけを足す。**オプトアウト（届け出が必要／要配慮個人情報には使えない）には戻らない**。
  s09 の「受信を拒否するための連絡先」は L49 のオプトアウト制度とは別物なので、
  **意図的に「オプトアウト」とは呼ばず**「受信拒否」で通す
- **L17（デジタル署名）の呼称に従う**。技術の側は「デジタル署名」、法律が効力を与える側の署名は
  「電子署名」で呼び分ける（L17 の呼称表が「電子署名と言い換えない・電子署名法は L52」と決めている）
- **L21（PKI・認証局）の呼称に従う**。認証局の技術的な仕組み（ルート証明書・信頼の連鎖・CRL）には
  戻らず、s06 で「認証局を法制度の側から見たもの」と一言つなぐだけ
- **L44（メールの技術対策）とは重ならない**。OP25B・ベイジアンフィルタリングなど
  迷惑メールの技術対策には触れない（L44 の narration が「特定電子メール法は L52」と明記している）

### 扱わない（発注書どおり）

- デジタル署名・タイムスタンプの技術 → L17（s04 で1文つなぐだけ）
- 認証局・証明書の技術的な仕組み → L21（s06 で1文つなぐだけ）
- 迷惑メールの技術対策（OP25B・フィルタリング）→ L44（語も出さない）
- 偽・誤情報（ディスインフォメーション等）・ファクトチェック → L54（語も出さない）
- 暗記カードなど他機能への誘導文は書かない（動画は1本で完結させる決まり）

## 用語の呼称（この回が正）

| 用語 | この回での言い方 |
|---|---|
| 電子署名法 | 正式には**電子署名及び認証業務に関する法律**。**電子の文書に、紙と同じ効力を与える法**。L17 で学んだデジタル署名という技術に、法律の効力を与える側 |
| 電子署名 | 法律が効力を与える側の署名（技術そのものを指すときは L17 に揃えて「デジタル署名」と呼ぶ） |
| 成立の推定 | 電子文書に**本人による電子署名**があれば、**真正に成立したものと推定される**。＝本人が押印した紙の文書と同じ扱い（R5問8の題材） |
| 認証業務 | 「その電子署名は本人のものだ」と示すために**電子証明書を発行する**業務 |
| 認定認証事業者 | 一定の基準を満たすとして**国が認定した**認証業務の事業者。L21 の認証局を法制度の側から見たもの |
| 特定電子メール法 | **広告宣伝のメール**を対象にする法律 |
| オプトイン | **あらかじめ同意した人にしか送れない**（L49 の「先に同意をもらう方式」を受けて再定義しない） |
| 同意の記録 | 同意をもらった記録は**保存しておく必要がある** |
| 表示義務 | 送信者の**氏名や名称・連絡先**をメールに書く義務 |
| 受信拒否 | **受信を拒否するための連絡先**を示す義務（＝配信停止のリンク）。拒否した人へ送り続けることはできない。**L49 の「オプトアウト」とは呼ばない**（別制度） |
| 情報流通プラットフォーム対処法 | **SNSなどの大規模なプラットフォーム**が対象。誹謗中傷の投稿への**削除対応の体制**を求め、**判断の基準と対応状況の公表**も義務づける |

## ナレーション原稿

### s02 導入 — ハンコを押さない契約
1. 契約書にハンコを押さず、画面の上で署名する。
2. これで本当に、契約は成立するのでしょうか。
3. 答えを決めているのは、技術ではなく法律です。
4. 今回は、身近な場面を支える三つの法律を見ていきます。

### s03 見取り図 — 場面ごとに担当する法律
1. 今回の舞台は、電子の署名、広告のメール、ネット上の投稿です。
2. 一つ目の電子署名法は、電子の文書に紙と同じ効力を与えます。
3. 二つ目の特定電子メール法は、広告メールの送り方を決めます。
4. 三つ目の情報流通プラットフォーム対処法は、投稿への対応です。
5. 場面ごとに、担当する法律が決まっています。

### s04 電子署名法
1. まずは、電子署名法です。
2. 正式には、電子署名及び認証業務に関する法律といいます。
3. 以前学んだデジタル署名は、本人が作ったことを示す技術でした。
4. その技術による署名に、法律の効力を与えるのが、この法律です。
5. 紙のハンコにあたる役割を、電子の署名に持たせます。

### s05 成立の推定
1. この法律の中心にあるのが、成立の推定という考え方です。
2. 電子文書に、本人による電子署名があるとします。
3. するとその文書は、真正に成立したものと推定されます。
4. つまり、本人が押印した紙の文書と同じ扱いになります。
5. 電子契約サービスで結んだ契約書も、証拠として通用します。

### s06 認定認証事業者と電子証明書
1. では、その署名が本人のものだと、誰が示すのでしょうか。
2. その役目を担うのが、電子証明書を発行する認証業務です。
3. 一定の基準を満たす事業者を、国が認定します。
4. これを、認定認証事業者といいます。
5. 以前学んだ認証局を、法制度の側から見たものです。

### s07 特定電子メール法とオプトイン（wipe-light）
1. 次は、広告のメールに関する法律です。
2. 特定電子メール法といい、広告宣伝のメールが対象です。
3. 原則は、以前学んだオプトインです。
4. あらかじめ同意した人にしか、送ってはいけません。
5. 同意していない相手へ一方的に送ることは、認められません。

### s08 ★抽象→具体：会員登録フォームのチェック欄
1. 場面で見てみましょう。ネットショップの会員登録フォームです。
2. 広告メールを受け取る、というチェック欄があります。
3. ここにチェックを入れた人だけが、送ってよい相手です。
4. しかも、同意をもらった記録は保存しておく必要があります。

### s09 送信者の義務（表示と受信拒否）
1. 送るときにも、決められた表示があります。
2. 送信者の氏名や名称、そして連絡先を書かなければなりません。
3. さらに、受信を拒否するための連絡先も示します。
4. メールの下にある配信停止のリンクが、まさにこれです。
5. 拒否した人へ、その後も送り続けることはできません。

### s10 情報流通プラットフォーム対処法
1. 最後は、ネット上の投稿をめぐる法律です。
2. 情報流通プラットフォーム対処法といいます。
3. SNSなどの、大規模なプラットフォームが対象です。
4. 誹謗中傷の投稿を削除するかどうか、対応する体制を求めます。
5. どんな基準で判断し、どう対応したかの公表も必要です。
