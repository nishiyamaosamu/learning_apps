## 原稿（字幕＝読み上げテキスト。1文＝1セグメント＝字幕1枚）

### s02 導入：事故は起きる（custom：左イラスト scene-incident.png ＋右テキスト）
1. 今回は、インシデントハンドリングとセキュリティ組織について学びます。
2. どれだけ備えても、事故が起きてしまうことはあります。
3. 大事なのは、起きたあとに誰が何をするかが決まっているかです。
4. その動き方と、担う組織をまとめて押さえていきます。

### s03 事象とインシデント（custom：包含図）
1. まず、言葉の区別から入ります。
2. 気づいた出来事そのものを、情報セキュリティ事象と呼びます。
3. そのうち、実害が出た、または出そうなものが情報セキュリティインシデントです。
4. 事象は日々いくつも起きるので、インシデントを見分けるのが最初の仕事です。

### s04 ハンドリングの4ステップ（custom：横4ステップの帯）★背骨
1. 動き方は、四つのステップで押さえます。
2. 最初は検知・連絡受付で、監視や連絡で気づき、窓口で受け付けます。
3. 次がトリアージで、どれから対応するかの順位を決めます。
4. そしてインシデントレスポンスで、被害を広げない手当てをします。
5. 最後に報告・情報公開で、経営層や関係先に伝えます。

### s05 トリアージ（vs：医療の現場／セキュリティ）
1. 四つの中で、聞き慣れないのがトリアージでしょう。
2. もともとは医療の言葉で、けが人が同時に出たときの治療の順番を決めることです。
3. セキュリティでも連絡は同時に入るので、全部に一度は対応できません。
4. 影響の大きさと緊急度から、対応の順番を決めます。

### s06 具体場面：ある朝の三件（custom：時刻つき4行）★抽象→具体
1. 具体的な場面で見てみましょう。
2. ある朝、社内から三件の連絡が届き、担当チームが受け付けました。
3. 顧客情報が漏れた疑いを最優先と決め、その端末をネットワークから切り離します。
4. 原因を確かめて元に戻し、その日のうちに経営層へ報告しました。

### s07 レスポンスとテイクダウン（custom：左2行＋右キーワード見出し）
1. インシデントレスポンスは、被害を広げないための手当てです。
2. 感染した端末を切り離したり、危ないサービスを一時的に止めたりします。
3. 攻撃に使われている外部の仕組みを止めさせる対応が、テイクダウンです。
4. 自社をかたる偽サイトや、指令を出すC&Cサーバが対象です。
   （※ 音声用テキストのみ「シーアンドシーサーバ」と仮名書き。読みは L5 に揃えた。字幕は「C&Cサーバ」）

### s08 インシデントに備える組織（custom：2段の組織地図・wipe-lightで章転換）
1. ここからは、備える組織を見ていきます。
2. 方針と体制を決めるのが、情報セキュリティ委員会です。
3. 決まったことにもとづいて実際に動くのが、CSIRT（シーサート）です。
4. 自社製品の脆弱性やインシデントに対応するのが、PSIRT（ピーサート）です。
5. 24時間の体制で監視し、異常を見つけるのがSOC（ソック）です。
   （※ CSIRT・PSIRT・SOC は音声用テキストのみ「シーサート」「ピーサート」「ソック」と仮名書き。
   定着した読み方があるので字幕には初出の1回だけ読みを添える。
   「24時間」も音声側だけ「にじゅうよじかん」と仮名書き）

### s09 エシカルハッカー（custom：キーワード見出し＋右イラスト person-auditor-magnifier.png）
1. もう一つ、押さえたい役割があります。
2. 攻撃者と同じ技術を、守る側で使う人をエシカルハッカーと呼びます。
3. 弱点を先に見つけて直すために、攻撃者の目で自社を調べます。
4. 実際に攻撃を試すやり方は、のちの回でくわしく学びます。

### s10 同じ言葉が二つの分野に（custom：2枚カード・イラスト入り）★L68との区別
1. 最後に、言葉の注意点です。
2. インシデント管理という言葉は、サービスマネジメントの分野でも使われます。
3. そちらは、サービスの障害をできるだけ早く元に戻すための活動です。
4. 同じ名前でも別の枠組みなので、のちの章でもう一度整理します。
