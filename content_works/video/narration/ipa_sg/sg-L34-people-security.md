## 用語の呼称（L6 に揃えた／この回で新しく定義した語）

| 語 | この回での言い方 |
|---|---|
| 不正のトライアングル | 機会・動機・正当化の3つがそろったときに不正は起こる（**L6 の定義をそのまま受ける**） |
| 機会 | 権限を必要な分だけにして、記録が残るようにして減らす（＝L6「組織が直接手を出せるのは主に機会」の対策側） |
| 動機 | 相談できる窓口や、納得できる評価のしかたで和らげる |
| 正当化 | ルールをはっきり示し、約束を交わすことでさせない |
| 組織における内部不正防止ガイドライン | 内部不正を防ぐための実務のまとめ。トライアングルを対策の側から整理してくれる |
| 情報セキュリティの啓発と教育 | 全員に基本を浸透させる、終わりのない活動。忘れる・手口が変わるので繰り返す |
| 標的型メール訓練 | 本物そっくりの訓練メールを社員に送る訓練。**開いた人を責めない**。組織の弱点を知り備えを鍛えるのがねらい |
| レッドチーム演習 | 攻撃役のチームが本気で攻め、守る側が気づけるか・正しく動けるかを試す。ペネトレーションテスト（L33）との違いは**人と組織まで試す**こと |
| 認証情報の割当てと管理 | アカウントを渡す時と取り上げる時を決める手続き。入社＝必要な分だけ／異動＝渡し直す／退職＝その日のうちに止める |
| セキュリティクリアランス | その人が扱ってよい情報のレベルをあらかじめ決めておく考え方 |
| 秘密保持契約・誓約書 | 約束で縛る対策。技術が効くのは在職中だけだが、約束は辞めたあとまで効き続ける |

## 範囲の切り分けメモ

- **不正のトライアングル・状況的犯罪予防・割れ窓理論の"定義"には戻らない**（L6 が主担当）。
  s04 は「三つがそろうと起こる」の一言だけで受け、以降は**対策の側**だけを語る
- アクセス権の設定・特権管理（技術側の統制）は **L36** なので、s08 は「アカウントを渡す／
  取り上げる**手続き**」に限定し、権限設計の話には踏み込まない
- 秘密保持契約の法的な扱い・労働法制は **L53**。s10 は「約束は辞めたあとまで効く」までで止める
- 教育・訓練計画の提案／内部不正のケース演習は **L95（科目B）**
- ペネトレーションテストの中身は **L33**。s07 では違いを言うために名前を出すだけ
- IPA・JPCERT/CC などの機関名は **L31** の領分なので、ガイドラインの発行元は語らない
- ブルーチームは発注書に無いので出さず、「守る側」と呼ぶ

## 原稿（字幕＝読み上げテキスト。1文＝1セグメント＝字幕1枚）

### s02 導入（custom：左イラスト person-employee-f-worry.png ＋右テキスト）
1. 今回は、人的セキュリティ対策について学びます。
2. どれだけ機器で固めても、鍵を開けてしまうのは人です。
3. だから人は、組織で最大の弱点であり、同時に最初の防衛線になります。
4. 教育と訓練と約束で、その人の穴をふさいでいきましょう。

### s03 内部不正防止ガイドライン（custom：中央キーワード見出し）
1. まず、内部不正を防ぐための実務のまとめがあります。
2. 組織における内部不正防止ガイドラインです。
3. 前に学んだ不正のトライアングルを、対策の側から整理してくれます。

### s04 ★三つのどれを潰すか（custom：3カード＋結論バンド）
1. 不正は、機会、動機、正当化の三つがそろったときに起こります。
2. 機会は、権限を必要な分だけにして、記録が残るようにして減らします。
3. 動機は、相談できる窓口や、納得できる評価のしかたで和らげます。
4. 正当化は、ルールをはっきり示し、約束を交わすことでさせません。
5. どれを潰すのかを決めてから、対策を選ぶのがこつです。

### s05 啓発と教育（custom：左テキスト＋右イラスト mgmt-education.png）
1. 次は、情報セキュリティの啓発と教育です。
2. 全員に基本を浸透させる、終わりのない活動です。
3. 人は忘れますし、攻撃の手口も変わるので、一度だけでは足りません。
4. だから、形を変えて繰り返し伝えることが必要になります。

### s06 標的型メール訓練（custom：訓練メールのモックカード／wipe-lightで章転換）
1. 教えたことが身についているかは、訓練で確かめます。
2. 標的型メール訓練では、本物そっくりの訓練メールを社員に送ります。
3. ここで大事なのは、開いてしまった人を責めないことです。
4. どこが弱いのかを組織として知り、備えを鍛えるのがねらいです。

### s07 レッドチーム演習（vs：ペネトレーションテスト ↔ レッドチーム演習）
1. もっと本格的に試すのが、レッドチーム演習です。
2. 攻撃役のチームが、実際の攻撃者のように本気で攻めてきます。
3. 試されるのは、守る側が気づけるか、正しく動けるかです。
4. 前回のペネトレーションテストとの違いは、人と組織まで試すことです。

### s08 認証情報の割当てと管理（custom：横帯3段＋注意バンド）
1. 人に何を渡し、いつ取り上げるかを決めるのが、認証情報の割当てと管理です。
2. 入社のときは、必要な分だけを渡します。
3. 異動したら渡し直し、退職の日には、その日のうちに止めます。
4. 止め忘れた退職者のアカウントは、内部不正の入口になります。

### s09 セキュリティクリアランス（custom：情報レベルの3段＋人のバッジ）
1. 情報の側から見ると、セキュリティクリアランスという考え方があります。
2. その人が扱ってよい情報のレベルを、あらかじめ決めておくことです。
3. 適性を確かめたうえで、機密に触れられる範囲を人ごとに決めます。

### s10 秘密保持契約・誓約書（custom：時間軸ストリップ＋イラスト mgmt-contract.png）
1. 最後は、約束で縛る対策です。
2. 秘密保持契約や誓約書を、入社のときや退職のときに交わします。
3. 技術で守れるのは、その人が社内にいる間だけです。
4. 約束なら、辞めたあとまで効き続けます。

### s11 ★抽象→具体：Aさんの最終出社日（custom：横3タイル＋結果バンド）
1. たとえば、顧客名簿を扱っていた営業のAさんが退職する日を考えます。 ※音声は「エーさん」
2. まず、秘密は退職後も守ると書いた誓約書に、署名してもらいます。
3. 次に、貸していた端末を返してもらいます。
4. そしてその日のうちに、Aさんのアカウントを止めます。 ※音声は「エーさん」
5. これで顧客名簿には入れなくなり、持ち出す機会が消えます。
