## 原稿（字幕＝読み上げテキスト。1文＝1セグメント＝字幕1枚）

### s02 導入：なぜ暗号が要るのか（custom：左テキスト＋右イラスト tech-encrypt.png）
1. 今回は、情報を守る基本の技術、暗号方式を学びます。
2. インターネットを流れるデータは、途中で盗み見られる危険があります。
3. そこで、内容を読めない形に変えてから送るのが暗号化です。
4. 鍵を持っている相手だけが、元の内容に戻すことができます。

### s03 用語の整理（custom：横一列の変換フロー）
1. まず、言葉の意味を整理しておきましょう。
2. もとの読める情報を平文（ひらぶん）、変換されたものを暗号文と呼びます。
3. 平文を暗号文に変えることが暗号化、もとに戻すことが復号です。

※ **難読語の例外**（s03-2・s03-3）: 「平文」は TTS が「へいぶん」と読んでしまうため、
**音声と字幕でテキストを分けている**。`N()` の第2引数は字幕にしか使われず、音声は mp3 ファイル
そのものなので、両者が食い違っても再生には影響しない。

| | テキスト |
|---|---|
| 音声（`jobs.json`） | s03-2「もとの読める情報を**ひらぶん**、…」／ s03-3「**ひらぶん**を暗号文に…」 |
| 字幕（`.tsx` の `N()`） | s03-2「もとの読める情報を**平文（ひらぶん）**、…」／ s03-3「**平文**を暗号文に…」 |

読みを添えるのは初出の s03-2 だけ（毎回添えると字幕がうるさくなる）。
音声を後から直すときは `jobs.json` 側を編集して該当ファイルだけ再生成する。
4. このとき使う秘密の情報が、暗号鍵と復号鍵です。

### s04 共通鍵暗号方式（custom：送受信フロー＋両端に同じ鍵 icon-key.png）
1. 一つ目の方式は、共通鍵暗号方式です。
2. 暗号化と復号に、まったく同じ鍵を使う方式です。
3. 処理が速く、大量のデータを扱うのに向いています。
4. 代表的な方式が、AESです。
5. ただし、その鍵を相手へ安全に渡す方法が課題になります。

### s05 公開鍵暗号方式（custom：左イラスト icon-key-pair.png＋右カード2枚）
1. 二つ目の方式は、公開鍵暗号方式です。
2. 鍵をペアで作り、公開鍵は誰にでも配り、秘密鍵は自分だけが持ちます。
3. 送る人は、受け取る人の公開鍵を使って暗号化します。
4. 対応する秘密鍵を持つ本人だけが、復号できます。
5. 代表的な方式が、RSA暗号です。

### s06 鍵の数（custom：数字ドン）
1. 二つの方式は、必要な鍵の数も大きく違います。
2. 共通鍵は相手ごとに別の鍵がいるので、百人だと四千九百五十本も必要です。
3. 公開鍵なら、一人が一組の鍵を持つだけで足ります。

### s07 2方式の対比（vs・wipe-lightで章転換）
1. ここで、二つの方式を比べて整理しましょう。
2. 共通鍵は処理が速い一方、鍵を安全に渡す手段が課題になります。
3. 公開鍵は鍵を配れるので安全ですが、処理に時間がかかります。

### s08 ハイブリッド暗号方式（custom：2段の帯 STEP1／STEP2）
1. そこで、両方の良いところを組み合わせたのがハイブリッド暗号方式です。
2. はじめに、公開鍵暗号方式を使って、共通鍵を安全に相手へ渡します。
3. そのあとは、渡した共通鍵で本文を高速にやり取りします。
4. ウェブを暗号化するTLSも、この仕組みを使っています。

### s09 具体シーン：ネットショップで何が暗号化されるのか（custom：場面図）
1. では、買い物の場面で、何が暗号化されるのかを見てみましょう。
2. カード番号を入力すると、ブラウザはその場で共通鍵を一つ作ります。
3. その共通鍵を、お店の公開鍵で暗号化して送ります。
4. お店は自分の秘密鍵でロックを外し、同じ共通鍵を取り出します。
5. そのあと、カード番号や住所といった注文の中身を、この共通鍵で暗号化します。
6. 公開鍵で守るのは共通鍵だけで、中身のデータは共通鍵が守ります。

s08 が「手順」の説明なので、このページは「暗号化される中身は2つあり、それぞれ別の鍵で
守られる」を場面で見せる役割にした（この回でいちばん誤解されやすい点）。画面は
左「あなた」・右「ショップ」の間に荷物のレーンを2本置き、①共通鍵（店の公開鍵でロック）→
店が秘密鍵で開ける → ②カード番号・住所（共通鍵でロック）の順に語りへ同期して埋まる。

※ 枠だけ先に出して中身を後から入れる組み方は試して却下（空の白いカードが数秒居座ると
未完成の画面に見えた）。1文目の間は左右の当事者アイコンだけの疎な画面になるが、
場面の顔見せとして成立するのでこれでよい。

### s14 まとめ（summary・wipeで転換・共通音声 OUTRO_SEG）
1. 共通鍵暗号方式は同じ鍵を使い、速いかわりに鍵の受け渡しが課題です。
2. 公開鍵暗号方式は公開鍵で暗号化し、秘密鍵で復号します。
3. この二つを組み合わせたものが、ハイブリッド暗号方式です。
