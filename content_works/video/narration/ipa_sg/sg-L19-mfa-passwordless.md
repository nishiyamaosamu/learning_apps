## 原稿（読み上げ＝字幕）

**P2 パスワード1本の限界**（s02・133字）
1. 前回は、パスワードで本人を確かめるしくみを学びました。
2. でも、どれだけ長いパスワードでも、漏れてしまえばそれ一つで突破されます。
3. そこで今回は、パスワード一本に頼らない方法を学びます。
4. 考え方は、大きく二つあります。
5. 違う種類の証拠を重ねるか、覚える秘密そのものをなくすかです。

**P3 認証の3要素**（s03・143字）
1. 認証の手がかりは、大きく三つの種類に分けられます。
2. 一つ目は記憶で、パスワードのように本人だけが知っているものです。
3. 二つ目は所有で、スマートフォンやICカードのように本人だけが持っているものです。
4. 三つ目は生体で、指紋や顔のように本人自身の特徴です。
5. この三つが、今回の話の土台になります。

**P4 多要素認証**（s04・118字）
1. この三つのうち、種類の違うものを組み合わせるのが多要素認証です。
2. たとえば、パスワードに加えて、スマートフォンに届く番号を入力する方式です。
3. これは記憶と所有、二つの種類を重ねています。
4. 片方が漏れても、もう片方がなければログインできません。

**P5 多要素認証と多段階認証の違い**（s05・137字）
1. ここが試験でよく問われる急所です。
2. パスワードのあとに秘密の質問に答える方式は、確認を二回おこなっています。
3. これは多段階認証ですが、多要素認証ではありません。
4. どちらも記憶で、同じ種類の証拠を二回たずねているだけだからです。
5. 効くのは回数ではなく、種類の違う要素を重ねることです。

**P6 リスクベース認証**（s06・136字）
1. とはいえ、毎回二つの確認を求められると面倒です。
2. そこで使われるのが、リスクベース認証です。
3. いつもの端末やいつもの場所からのログインは、そのまま通します。
4. 見慣れない端末や、遠い国からのアクセスのときだけ、追加の確認を求めます。
5. 安全性と使いやすさの、折り合いをつけるしくみです。

**P7 パスワードレス認証**（s07・155字）
1. もう一つの方向が、覚える秘密そのものをなくす、パスワードレス認証です。
2. 代表的なしくみが、FIDO（ファイド）と呼ばれる規格です。
3. 本人を確かめる秘密は、利用者の端末の中だけに保管されます。
4. サーバーには秘密を預けないので、サーバーから漏れるものがありません。
5. 利用者は、端末のロックを解除するだけでログインできます。

**P8 シングルサインオン**（s08・138字）
1. 次は、シングルサインオンです。
2. 一度認証すれば、複数のサービスをそのまま利用できるしくみです。
3. 社内システムやクラウドサービスに、入り直す手間がなくなります。
4. ただし、その一回の認証が破られると、つながる全部に入られてしまいます。
5. だからこそ、入口の認証を多要素にしておくことが大切です。

**P9 CAPTCHA**（s09・120字）
1. 最後に、CAPTCHA（キャプチャ）です。
2. ゆがんだ文字を読ませたり、私はロボットではありませんに印を付けさせる、あの画面です。
3. これは、相手が人間かプログラムかを見分けるしくみです。
4. 本人が誰かを確かめるものではなく、機械による大量のログイン試行を防ぐためのものです。

**P11 クイズ1**（s11・62字）
1. ここで問題です。
2. パスワードのあとに秘密の質問に答える方式は、どちらでしょうか。
3. 正解は、多要素認証ではない、です。（考える間 1.8秒）

1. 次の問題です。
2. リスクベース認証は、どんなときに追加の確認を求めるでしょうか。
3. 正解は、いつもと違うときです。（考える間 1.8秒）

**P14 まとめ**（s14・91字）
1. 認証の要素は、記憶、所有、生体の三つです。
2. 種類の違う要素を重ねるのが多要素認証で、回数を重ねる多段階認証とは違います。
3. リスクベース認証やパスワードレス認証は、安全と便利を両立させます。
