## 用語の呼称（★この回が主担当。後続の回はこの表に揃える）

| 語 | この回での言い方 |
|---|---|
| **アクセス制御** | 誰がどの情報にどこまで触れてよいかを決めて、守らせる仕組み。決めることは**「誰が・どの情報を・どう扱えるか」の三つ** |
| **アクセス権の設定** | 縦に利用者やグループ、横に読む・書く・実行するを並べた**表**の形になる。手間を減らすため**部署などのグループ単位**で割り当てるのがふつう |
| **最小権限の原則** | 業務に必要な人に、必要な範囲だけを与える（**L22 s06 の言い方をそのまま継承**） |
| **need-to-know** | 「知る必要がある人にだけ知らせる」。**ニードトゥノウ**とカタカナで呼ぶ（最小権限の言い換えとして紹介する。L22 と同じ扱い） |
| **アクセス権の見直し（棚卸し）** | 権限は**足し算ばかりになる**ので、異動・退職・担当替えのたびに「いま本当に必要か」を確かめて外す |
| **特権的アクセス権** | システムの管理者に与えられる、**ほとんど何でもできる権限**。守り方は「**人を絞る／IDを共有しない／操作を記録する**」の三つ |
| **セキュアOS** | 「**管理者でも何でもはできない**」という発想を OS に組み込んだもの。強制アクセス制御と管理者権限の分割が柱 |
| **強制アクセス制御** | 利用者ではなく、**システムの側が決めた規則**で許可を判断する方式 |
| **ゼロトラスト** | 「社内だから信用する」をやめる考え方。**場所ではなく、アクセスのたびに毎回確かめる** |
| **境界防御（対比のみ）** | 社内と社外の境目に壁を作る、これまでの守り方。**仕組みの中身は L38** なので名前と発想だけで止める |
| **検疫ネットワーク** | つなぐ前に検査する仕組み。持ち込んだPCをいきなり社内LANに入れず、**隔離した専用のネットワーク**で健全性を確かめてから通す |

## 原稿

### s02 導入（custom：左テキスト＋右イラスト tech-gate.png）
1. 情報を守る対策のなかで、毎日いちばん使われているのがアクセス制御です。
2. 建物に鍵をかけても、入った人が全部の部屋を開けられたら、守れているとは言えません。
3. 誰に、何を、どこまで許すのか。その仕組みを学びます。

### s03 アクセス制御とは（custom：中央キーワード見出し＋3チップ）
1. アクセス制御とは、誰がどの情報にどこまで触れてよいかを決めて、守らせる仕組みです。
2. 決めることは三つ。誰が、どの情報を、どう扱えるか、です。
3. この三つの組み合わせが、そのまま権限になります。

### s04 アクセス権の設定（custom：権限表グリッド）
1. 実際の設定は、こんな表のかたちになります。
2. 縦に利用者やグループ、横に読む、書く、実行するといった操作を並べます。
3. 一人ずつ設定すると手間がかかるので、ふつうは部署などのグループ単位で割り当てます。

### s05 最小権限の原則（custom：左キーワード見出し＋右の絞り込み図）★主担当
1. ここで大切になるのが、最小権限の原則です。
2. 業務に必要な人に、必要な範囲だけを与える、という考え方です。
3. 知る必要がある人にだけ知らせる、ニードトゥノウとも呼ばれます。
4. 全員に全部を許すと、一つのアカウントが乗っ取られただけで、すべてが漏れます。

### s06 権限は足し算になる（custom：横の時間ストリップ＋イラスト）★抽象→具体
1. たとえば、営業部のBさんが経理部へ異動したとします。
   （※ 音声のみ「ビーさん」。字幕は「Bさん」）
2. 経理のシステムを使うために、新しい権限が追加されます。
3. ところが、営業の顧客名簿を見られる権限は、そのまま残りがちです。
4. こうして権限は足し算ばかりになり、一人の届く範囲が広がっていきます。
5. だから異動や退職のたびに棚卸しをして、いらない権限を外します。

### s07 特権的アクセス権（custom：用語見出し＋3カード・wipe-lightで章転換）
1. 権限のなかでも特別な扱いが必要なのが、特権的アクセス権です。
2. システムの管理者に与えられる、ほとんど何でもできる権限のことです。
3. 使える人を絞り、IDを複数人で共有しないことが基本です。
   （※ 音声のみ「アイディー」。字幕は「ID」）
4. そのうえで、特権での操作はすべて記録に残します。

### s08 セキュアOS（custom：上下2段のバンド図）
1. 管理者でも何でもはできない、という発想をOSに組み込んだものがセキュアOSです。
   （※ 音声のみ「オーエス」「セキュアオーエス」。字幕は「OS」「セキュアOS」）
2. 利用者ではなく、システムの側が決めた規則で許可を判断します。
3. これを強制アクセス制御と呼びます。
4. さらに管理者の権限を分割し、乗っ取られても被害が限定されるようにします。

### s09 ゼロトラスト（vs：境界防御 ↔ ゼロトラスト）
1. これまでの守り方は、社内と社外の境目に壁を作るものでした。
2. でも、社内の人が悪意を持つこともあれば、社外から働く人もいます。
3. そこで、社内だから信用する、をやめたのがゼロトラストです。
4. 場所ではなく、アクセスのたびに毎回確かめます。

### s10 検疫ネットワーク（custom：3段フロー＋右イラスト tech-quarantine.png）
1. その発想を形にした仕組みが、検疫ネットワークです。
2. 持ち込んだパソコンを、いきなり社内のネットワークにはつなぎません。
3. まず隔離した専用のネットワークで、健全かどうかを検査します。
4. 修正プログラムやウイルス対策が最新かを確かめて通します。

### 幕間（共通音声 QUIZ_INTRO_SEG・SectionTitle「クイズで確認」）

### s12 クイズ①（最小権限・正解B）
1. 一問目です。
2. 最小権限の原則に沿った設定は、どちらでしょうか。
3. （考える間 1.8秒）正解は、Bの業務で使う範囲だけを与える、です。
4. 全員に同じ権限をまとめて付けると、必要のない情報にまで手が届きます。

### s13 クイズ②（特権IDの共有・正解A）
1. 二問目です。
2. 管理者のIDを複数人で共有すると、何が問題になるでしょうか。
   （※ 音声のみ「アイディー」）
3. （考える間 1.8秒）正解は、Aの誰の操作か分からなくなる、です。
4. 記録は残っても、操作した人にたどり着けなくなってしまいます。

### s14 クイズ③（ゼロトラスト・正解B）
1. 最後の問題です。
2. ゼロトラストの考え方に近いのは、どちらでしょうか。
3. （考える間 1.8秒）正解は、Bの場所で信用せず毎回確かめる、です。
4. 社内にいることは、もう安全の証明にはならないという前提に立ちます。

### s15 まとめ（summary・wipe）
1. 今回のまとめです。
2. アクセス制御は、誰に何をどこまで許すかを決め、最小限に絞るのが基本です。
3. 特権的アクセス権は、人を絞り、共有せず、操作を記録します。
4. 社内という場所を信用しないのが、ゼロトラストと検疫ネットワークの発想です。
5. （共通音声 OUTRO_SEG）
