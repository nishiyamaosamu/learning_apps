## 原稿（字幕＝読み上げテキスト。1文＝1セグメント＝字幕1枚）

### s02 導入：改ざんを見抜きたい（custom：左テキスト＋右イラスト tech-hash.png）
1. 今回は、ハッシュ関数と鍵管理について学びます。
2. 受け取ったファイルが、途中で書き換えられていないか気になることはありませんか。
3. 中身をすべて見比べなくても、改ざんを見抜ける仕組みがあります。
4. それが、もとに戻せない変換を行うハッシュ関数です。

### s03 ハッシュ関数とメッセージダイジェスト（custom：3行の変換表）
1. ハッシュ関数は、入力されたデータから短い値を計算する関数です。
2. できあがった値をメッセージダイジェスト、または単にハッシュ値と呼びます。
3. 入力が一文字でも数ギガバイトでも、出てくる値の長さは必ず同じです。
4. 代表的なのはSHA-256（エスエイチエー256）で、常に256ビットです。

### s04 一方向性（custom：上下2段の帯。暗号化＝往復／ハッシュ＝片道）
1. ハッシュ関数の一つ目の性質が、一方向性です。
2. 暗号化なら、鍵があればもとの平文に戻すことができます。
3. ところがハッシュ値からは、もとのデータを復元できません。
4. 鍵がないから戻せないのではなく、そもそも戻す仕組みがないのです。

### s05 パスワードの保管（custom：保存テーブルのモック）
1. この一方向性は、パスワードの保管に使われています。
2. パスワードをそのまま保存すると、漏れたときに全員が悪用されます。
3. そこでハッシュ値だけを保存し、パスワード自体はどこにも残しません。
4. 入力された値のハッシュを計算し、保存された値と比べれば本人と確認できます。

### s06 衝突困難性と改ざん検知（custom：3カラムの突き合わせ）
1. 二つ目の性質が、衝突困難性です。
2. 同じハッシュ値になる別のデータを作り出すのは、非常に困難です。
3. だから、ハッシュ値が一致すれば中身も同じだと判断できます。
4. 配布元が公開した値と手元で計算した値を比べれば、改ざんに気づけます。

### s07 危殆化とCRYPTREC暗号リスト（custom：キーワード見出し＋icon-clock.png。wipe-lightで章転換）
1. ここからは、暗号を安全に使い続けるための話です。
2. 暗号やハッシュ関数は、計算機の性能が上がるほど破られやすくなります。
3. 安全性が時間とともに低下することを、危殆化（きたいか）と呼びます。
4. そこで国は、今使ってよい暗号を評価してリストにまとめています。
5. それがCRYPTREC（クリプトレック）暗号リストです。

### s08 鍵管理のライフサイクル（flow：生成→保管→更新→廃棄）
1. 次は、鍵そのものの管理です。
2. アルゴリズムがどれだけ強くても、鍵が漏れれば暗号は無意味になります。
3. 鍵は、生成、保管、更新、廃棄という一生を通して管理します。
4. まず推測されにくい鍵を作り、限られた人だけが取り出せる場所に保管します。
5. そして定期的に新しい鍵へ入れ替えます。
6. 使わなくなった鍵は、復元できない形で確実に捨てます。

### s09 保存データの暗号化（custom：左イラスト tech-cabinet.png＋右カード2枚）
1. 暗号化が守るのは、通信だけではありません。
2. 保存されたデータを守るのが、ストレージ暗号化とファイル暗号化です。
3. ストレージ暗号化は、ディスク全体をまるごと暗号化します。
4. ファイル暗号化は、重要な書類を一つずつ暗号化します。
5. 端末や記録媒体を盗まれても、中身を読み取られずに済みます。

### s10 クイズ幕間（SectionTitle・共通音声 QUIZ_INTRO_SEG）
1. ここまで学んだことを、クイズ形式で確認していきましょう。

### s11 クイズ①（一方向性・正解A）
1. ここで問題です。
2. ハッシュ値から、もとのデータを復元できるでしょうか。
3. （考える間 1.8秒）正解は、復元できない、です。一方向性があるからです。

### s12 クイズ②（改ざん検知・正解B）
1. 次の問題です。
2. 二つのファイルのハッシュ値が一致したとき、何が言えるでしょうか。
3. （考える間 1.8秒）正解は、中身が同じだと判断できる、です。

### s13 クイズ③（危殆化・正解A）
1. 最後の問題です。
2. 時間の経過とともに暗号の安全性が下がることを、何と呼ぶでしょうか。
3. （考える間 1.8秒）正解は、危殆化です。

### s14 まとめ（summary・wipeで転換・共通音声 OUTRO_SEG）
1. ハッシュ関数は固定長のハッシュ値を作り、もとには戻せません。
2. ハッシュ値が一致すれば中身も同じ、だから改ざんを見抜けます。
3. 鍵は生成から廃棄まで管理し、暗号の危殆化にも備えます。
4. 今回のレッスンはここまでです。お疲れさまでした！（共通音声）
