## 原稿（字幕＝読み上げテキスト。1文＝1セグメント＝字幕1枚）

### s02 導入：自社の外にも味方がいる（custom：左イラスト person-employee-m-worry.png ＋右テキスト）
1. 今回は、セキュリティに関わる機関と制度について学びます。
2. 前回は、社内に置くCSIRTなどの組織を見ました。
3. けれど、自社だけでは手に負えないことも起こります。
4. そんなときに頼れる先が、社外にも用意されています。

### s03 3層の地図（custom：縦3段の帯）★背骨
1. 関わる機関は多いので、まず地図を三つの層で持ちましょう。
2. 一番上は司令塔で、国として何をするかを決めます。
3. 真ん中は実働で、注意を呼びかけたり、対応を助けたりします。
4. 一番下は制度で、届け出たり、対策を認めたりする仕組みです。
5. この三つの層に、代表を当てはめていきます。

### s04 司令塔（custom：地図バー＋左カード〈戦略本部〉＋右キーワード見出し〈NISC〉）
1. まずは、一番上の司令塔です。
2. 国の方針を決めるのが、サイバーセキュリティ戦略本部です。
3. その事務局を務めるのが、内閣サイバーセキュリティセンターです。
4. 略してNISC（ニスク）と呼ばれます。
5. どちらもサイバーセキュリティ基本法にもとづく仕組みで、法律はのちの回で学びます。

### s05 実働の代表2つ（vs：IPAセキュリティセンター／JPCERT/CC）
1. 次は、真ん中の実働です。
2. 代表は二つで、IPAセキュリティセンターとJPCERT/CC（ジェーピーサート）です。
3. IPAは、注意喚起を出したり、届出の窓口を引き受けたりします。
4. JPCERT/CCは、インシデント対応の調整役として動きます。
5. 国内外の関係先をつないで、被害を広げない動きを作ります。

### s06 具体場面：弱点を見つけたら（custom：横4ノードの橋渡し図）★抽象→具体
1. 実働がどう働くのか、具体的な場面で見てみましょう。
2. あなたが、あるソフトウェアの弱点に気づいたとします。
3. 見つけた人はまずIPAに届け出て、JPCERT/CCが開発者へ連絡します。
4. 開発者が直したうえで、修正版と注意が公表されます。
5. この橋渡しの枠組みが、情報セキュリティ早期警戒パートナーシップです。

### s07 実働が動かす3つの仕組み（custom：縦3行リスト）
1. 実働の機関は、目的別の仕組みも動かしています。
2. J-CSIP（ジェイシップ）は、標的型攻撃の情報を企業のあいだで共有する取り組みです。
3. J-CRAT（ジェイクラート）は、相談を受けて被害の拡大を食い止めるレスキュー隊です。
4. JVNは、公表された脆弱性の情報をまとめて見られるデータベースです。

### s08 制度の代表3つ（custom：横3カード・wipe-lightで章転換）
1. 一番下の層は、制度です。
2. ISMAP（イスマップ）は、政府が使うクラウドサービスを評価して登録する制度です。
3. SECURITY ACTIONは、中小企業が対策への取り組みを自ら宣言する制度です。
4. NOTICEは、危ないIoT機器を調べて、利用者に注意を促す取り組みです。
5. どれも対象がはっきり違うので、対象で覚えると区別できます。

3. （考える間 1.8秒）正解は、JPCERT/CCで、国内外をつないで調整します。

### s11 クイズ②（脆弱性の届出先・正解B）
1. 次の問題です。
2. ソフトウェアの弱点を見つけたとき、届け出る先はどちらでしょうか。
3. （考える間 1.8秒）正解は、IPAで、そこから開発者へ橋渡しされます。

### s12 クイズ③（標的型攻撃の支援・正解A）
