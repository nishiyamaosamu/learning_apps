## 地図（この回の背骨）

**軸は「どこを守るか」**。各ページの分類チップは必ず「守る場所：◯◯」の形で置き、
いま地図のどのマスを見ているかを常に示す。

| # | 守る場所 | そのマスが引き受けること | この回で扱う代表 |
|---|---|---|---|
| 1 | 端末 | 使う人の手元のパソコン・スマートフォン | EDR・MDM |
| 2 | ネットワーク | 社内と外の境目、通信の出入り | UTM・WAF（＋前回のファイアウォール・IDS・IPS） |
| 3 | 情報 | データそのもの（どこにあっても） | DLP |
| 4 | 全体監視 | あちこちの記録をまとめて見る | SIEM |

「名前で覚えるのではなく、どこを守るかで引く」が覚え方。

## 用語の呼称（この回で決めた言い方）

| 語 | この回での定義（読み上げ文そのまま） |
|---|---|
| EDR | 端末のふるまいを記録し続ける仕組み。怪しい動きを見つけたらその端末を切り離す。**入口で止めるより、入られたあとを短くするのが役目** |
| MDM | 会社が配り、**社外へ持ち出す端末**（スマートフォン・タブレット・ノートパソコン）をまとめて管理する仕組み。ふだんは設定を配り・アプリの利用を制限し、紛失時は遠隔で画面を止めデータを消す。**「配ったスマートフォン」に限定しない** — 略語の訳（モバイル端末管理）の「モバイル＝スマホ」に引きずられて狭くしないこと（v1 で差し戻し） |
| UTM | 複数の防御機能を一つにまとめた製品。まとめて導入できるので中小規模の会社で使われる |
| WAF | Webアプリを狙う攻撃を防ぐ専門の盾。入力欄から不正な命令を送る攻撃を手前で止める |
| DLP | 守る対象を**データそのもの**に置いた製品。機密情報を見分けて持ち出し・送信をその場で止める。人や場所ではなく中身を見て判断する |
| SIEM | 機器ごとに散らばったログを集め、突き合わせて攻撃の兆候を浮かび上がらせる |
| 拒否リスト | 危ないものを一覧にして止める |
| 許可リスト | 安全と認めたものだけを通す（そのぶん業務は窮屈になる） |
| フォールスネガティブ | 危ないものを見逃すこと |
| フォールスポジティブ | 安全なものを誤って止めること（＝誤検知） |

## 範囲の切り分けメモ（発注書の「扱わない」を厳守）

- **ファイアウォール・IDS・IPS の仕組みは L38**。この回は s03-6 で「このマス（ネットワーク）に
  入ります」と**地図に置き直すだけ**。s06 の UTM の内訳チップに名前が並ぶが説明はしない
- SSL/TLSアクセラレーター・Webアイソレーション → 暗記カードの領分なので**名前も出さない**。
  他機能への誘導文も書かない（動画は1本で完結させる決まり）
- EDR が対応するマルウェアの手口 → L4・L5。s04-2 は「対策ソフトで入口を守っても、
  すり抜けてくるものはあります」まで
- マルウェア対策ソフトの検出手法（パターンマッチング・ビヘイビア法など）→ L35。
  s04-2 で「対策ソフト」と呼ぶだけで手法名には戻らない
- SQLインジェクション → L8。s06-5 は「入力欄から不正な命令を送る攻撃」と**平語**で言い、
  語は画面の小さな注記だけに置く（読み上げない）
- ログ管理そのもの（取る・見る・残す）→ L37。s08 は「散らばったログを集めて突き合わせる」＝
  製品側の話に限定し、画面注記「取るだけでは、誰も見ていない記録がたまる」で L37 を受けるだけ
- クラウドのセキュリティ → L55、IoT → L32、検疫ネットワーク／ゼロトラスト → L36 なので語を出さない

### s02 導入（custom：左イラスト person-employee-f-worry.png ＋右に略語チップ）
1. 今回は、セキュリティ製品とサービスの地図を作ります。
2. この分野は、アルファベットの略語が次々に出てきます。
3. 名前だけを覚えようとすると、すぐに混ざってしまいます。
4. そこで、どこを守る製品なのかで整理していきましょう。

### s03 ★4マスの地図（custom：横4マスのタイル）★背骨
1. 守る場所は、大きく四つに分けられます。
2. 一つ目は端末で、パソコンやスマートフォンを守ります。
3. 二つ目はネットワークで、社内と外の境目を守ります。
4. 三つ目は情報で、データそのものを守ります。
5. 四つ目は全体監視で、あちこちの記録をまとめて見ます。
6. ファイアウォールやIDS・IPSも、このマスに入ります。

### s04 端末の代表①：EDR（custom：左キーワード見出し＋右イラスト person-employee-m-laptop.png）
1. まずは、端末のマスから見ていきます。
2. 対策ソフトで入口を守っても、すり抜けてくるものはあります。
3. EDRは、端末のふるまいを記録し続ける仕組みです。
4. 怪しい動きを見つけたら、その端末を切り離せます。
5. 入口で止めるより、入られたあとを短くするのが役目です。

### s05 端末の代表②：MDM（custom：中央にノートPC＋スマホ＋左右2枚「ふだん／紛失時」）
1. 同じ端末のマスに、MDMがあります。
2. 会社が配って、社外へ持ち出す端末をまとめて管理する仕組みです。
3. スマートフォンやタブレット、ノートパソコンが対象です。
4. ふだんは設定を配り、勝手なアプリの利用を制限します。
5. 紛失したときは、遠隔で画面を止め、データを消せます。

画面には対象の端末チップ（スマートフォン／タブレット／ノートパソコン）を s05-3 の読み上げに
同期して出し、中央のイラストも `icon-laptop` ＋ `icon-smartphone` の2枚にしている
（**絵がスマホ1枚だと、語りを広げても対象が狭く見える**）。

### s06 ネットワークの代表：UTMとWAF（custom：左「まとめる箱」／右「一点を守る盾」）
1. 次は、ネットワークのマスです。
2. UTMは、複数の防御機能を一つにまとめた製品です。
3. まとめて導入できるので、中小規模の会社で使われます。
4. WAF（ワフ）は、Webアプリを狙う攻撃を防ぐ盾です。
5. 入力欄から不正な命令を送る攻撃を、手前で止めます。

### s07 情報の代表：DLP（custom：横フロー 機密データ→DLP→止まる出口2つ）
1. 三つ目は、情報のマスです。

3. 機密情報を見分けて、持ち出しや送信をその場で止めます。
4. 人や場所ではなく、中身を見て判断するのが特徴です。

### s08 全体監視の代表：SIEM（custom：上に散らばるログ→下の帯に集約）

## v2（rework対応）: MDM の対象端末を広げた

**指摘（人）: MDM はノートパソコンも含めて扱うこと。** v1 は s05・呼称表・クイズ解説のすべてを
「会社が配ったスマートフォン」に限定していて、対象が狭かった（画面のイラストも `icon-smartphone`
1枚のみ）。原因は **略語の日本語訳「モバイル端末管理」の『モバイル』をスマホと読んでしまったこと**。
実際の MDM は**社外へ持ち出す端末**（スマートフォン・タブレット・ノートパソコン）が対象。

直した4か所（1か所だけ直すと呼称表・語り・クイズが食い違うのでまとめて直した）:

1. **用語の呼称表の MDM の定義** — 「社外へ持ち出す端末（スマートフォン・タブレット・
   ノートパソコン）をまとめて管理する仕組み」に書き換え、狭くしない理由も添えた
2. **s05 のナレーション** — s05-2 を「会社が配って、社外へ持ち出す端末をまとめて管理する
   仕組みです。」に変え、**対象を名指しする s05-3「スマートフォンやタブレット、ノートパソコンが
   対象です。」を新設**（旧 s05-3・s05-4 は中身を変えず s05-4・s05-5 に番号を詰め直した＝
   音声ファイルも mv のみで再生成なし）
3. **クイズ①の正解解説（s13-3）** — 「端末をまとめて管理する仕組みです」→「社外へ持ち出す
   端末をまとめて管理します」（字幕29字。「スマートフォンやノートパソコンを…」だと字幕1行の
