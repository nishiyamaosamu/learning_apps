## この回の位置づけ

第6章（法務）の7本目。L47〜L52 が「法律そのもの」の回だったのに対し、この回は
**働く形（法律）と、仕事を頼む形（契約）**の2本柱で組む。

| 柱 | 中身 |
|---|---|
| 働く人を守る法律 | 労働基準法・就業規則 ／ 労働者派遣法（雇用と指揮命令の分離） |
| 仕事を頼むときの契約 | 請負契約・準委任契約（＋偽装請負）／ 守秘契約 ／ ソフトウェア使用許諾・コピーレフト ／ ソフトウェア開発委託モデル契約 |

### 隣の回との突合（L27・L34・L47・L51・L52 の narration を読んで確認済み）

- **罰則の扱いは L47〜L52 と揃える**。「無効です」「法律に違反します」までにとどめ、
  **刑名・年数・金額は出さない**（教材に揺れを持ち込まないため。試験で問われるのは
  「誰が指示できるか・何を約束したか」の側）
- **L47（知的財産権）**は「ソフトウェア使用許諾契約・コピーレフトは L53」と明記している。
  この回は契約で決める側だけを語り、**著作権の発生・保護対象・営業秘密の3要件には戻らない**
  （s10 で「著作権は作った側に残る」と1文つなぐだけ）
- **L34（人的セキュリティ）**は「秘密保持契約の法的な扱い・労働法制は L53」と明記し、
  s10 を「約束は辞めたあとまで効く」で止めている。この回の守秘契約は**取引の側**だけを扱い、
  入社・退職時の誓約書の運用には戻らない（s09 で「社員と交わす誓約書と合わせて」と1文つなぐだけ）
- **L27（情報セキュリティ諸規程）**は情報セキュリティポリシの階層（基本方針・対策基準・実施手順）が
  主題で、**就業規則には触れていない**。この回は「会社ごとの労働条件は就業規則に書かれ、
  情報の扱い方や懲戒もそこに書くから効き目を持つ」までを語り、**規程の階層には戻らない**
- **L51（刑法）・L52（電子署名法ほか）**とは語も重ねない（罪名・電子署名・広告メールは出さない）

## ナレーション原稿

### s02 導入 — 同じ職場、違う契約
1. 同じフロアで、机を並べて働く三人がいます。
2. 自社の社員、派遣社員、そして協力会社の技術者です。
3. 見た目は同じでも、誰の指示で働くかは別々です。
4. 今回は、働き方と発注を決める法律と契約を見ていきます。

### s03 見取り図 — 二つの柱
1. 今回の話は、大きく二つに分かれます。
2. 一つは、働く人を守る法律。労働基準法と労働者派遣法です。
3. もう一つは、仕事を頼むときに交わす契約です。
4. 請負や準委任、守秘契約、ソフトウェアの使用許諾。
5. どちらも、責任が誰にあるのかを決めています。

### s04 労働基準法と就業規則
1. まずは、労働基準法です。
2. 労働時間や賃金など、労働条件の最低の基準を定めます。
3. これを下回る取り決めは、社員が同意していても無効です。
4. 会社ごとの具体的な決まりは、就業規則に書かれます。
5. 情報の扱い方や懲戒も、就業規則に書くから効き目を持ちます。

### s05 労働者派遣法 — 雇用と指揮命令の分離
1. 次は、労働者派遣法です。
2. 派遣では、雇う会社と、指示を出す会社が分かれます。
3. 雇用契約を結び、給与を払うのは派遣元です。
4. 実際に仕事の指示を出すのは、派遣先です。
5. この、雇用と指揮命令の分離が、派遣の一番の特徴です。

### s06 請負契約と準委任契約（wipe-light）
1. ここからは、外部に仕事を頼むときの契約です。
2. 請負契約は、決められた成果物を完成させる約束です。
3. 完成しなければ、責任を問われます。
4. 準委任契約は、作業を任せる約束で、完成までは約束しません。
5. どちらも、発注側が作業者へ直接指示を出すことはできません。

### s07 偽装請負
1. ここで気をつけたいのが、偽装請負です。
2. 契約は請負なのに、発注側の社員が作業者へ直接指示を出す。
3. これは実態として労働者派遣にあたり、法律に違反します。
4. 指示を出したいなら、派遣の形で受け入れる必要があります。

### s08 ★抽象→具体：システム開発の委託
1. 場面で見てみましょう。システム開発をベンダに委託します。
2. 何を作るかを決める要件定義は、準委任契約が典型です。
3. 作るものが決まったあとの開発は、請負契約が典型です。
4. そのひな形が、ソフトウェア開発委託モデル契約です。
5. 役割分担のほか、秘密保持や検収の進め方も定めています。

### s09 守秘契約（NDA）
1. 取引では、相手の秘密に触れることがあります。
2. そこで交わすのが、守秘契約です。
3. 秘密保持契約とも呼ばれ、NDAと略されます。
4. 知った秘密を、目的以外に使わず、外に出さないと約束します。
5. 社員と交わす誓約書と合わせて、秘密を守る土台になります。

### s10 ソフトウェア使用許諾契約
1. 次は、ソフトウェアを買うときの契約です。
2. 買ったのは、そのソフトを使う権利です。
3. プログラムの著作権は、作った側に残ったままです。
4. だから、許諾の範囲を超えた複製や配布はできません。
5. 使う台数をまとめて買う形が、ボリュームライセンスです。

### s11 コピーレフト
1. 最後に紹介するのは、コピーレフトという考え方です。
2. 自由に使えるソフトの中には、条件がついたものがあります。
3. 改変して配るなら、同じ自由を引き継がせる、という条件です。
4. 自社のソフトに取り込む前に、条件を必ず確認します。
