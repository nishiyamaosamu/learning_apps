## 原稿（読み上げ＝字幕）

**P2 認証のしくみ**（s02・147字）
1. 前回は、パスワードを狙う攻撃を学びました。
2. 今回は、その攻撃から身を守る側にまわります。
3. ログイン画面には、利用者IDとパスワードを入れます。
4. 利用者IDは、自分が誰なのかを名乗るためのものです。
5. パスワードは、その人が本人であることを確かめるためのものです。
6. この二つがそろって、はじめて本人だと認められます。

**P3 パスワード強度は長さで決まる**（s03・139字）
1. まずは、パスワードの作り方です。
2. 総当たり攻撃に効くのは、複雑さよりも長さです。
3. 記号を混ぜた八文字よりも、意味のない言葉をつないだ二十文字のほうが強くなります。
4. 一文字増えるたびに、試すべき組み合わせは何十倍にもふくらみます。
5. 覚えやすくて長い、自分だけのフレーズを作るのがこつです。

**P4 使い回しをやめる**（s04・110字）
1. 次は、使い回しをやめることです。
2. パスワードリスト攻撃は、どこかで漏れた組み合わせをそのまま試します。
3. どれだけ長くて強いパスワードでも、使い回した瞬間に破られます。
4. サービスごとに違うパスワードにすることが、唯一の対策です。

**P5 チャレンジレスポンス認証**（s05・182字）
1. ここからは、パスワードを送るときの守り方です。
2. パスワードをそのままネットワークに流すと、盗聴されたときに読まれてしまいます。
3. そこで使われるのが、チャレンジレスポンス認証です。
4. サーバーは、毎回ちがうお題を利用者に送ります。
5. 利用者側は、そのお題とパスワードからハッシュ値を計算して返します。
6. サーバーも同じ計算をして答え合わせをするので、パスワードそのものは流れません。

**P6 ワンタイムパスワードとセキュリティトークン**（s06・144字）
1. 送るときのもう一つの工夫が、ワンタイムパスワードです。
2. 一度使ったら無効になる、使い捨てのパスワードです。
3. 通信の途中で盗み見られても、次のログインには使えません。
4. この使い捨ての番号を作り出す道具を、セキュリティトークンと呼びます。
5. 専用の小さな機器のほか、スマートフォンのアプリも使われます。

**P7 預けたパスワードはどう守られるか**（s07・135字）
1. では、預けたパスワードは、サービス側でどう守られているのでしょうか。
2. きちんとしたサービスは、パスワードそのものを保存していません。
3. ハッシュ関数で計算したハッシュ値だけを保存し、ログインのたびに照合します。
4. だから、忘れたときに元のパスワードを教えてもらうことはできません。

**P8 パスワードリマインダの落とし穴**（s08・164字）
1. そこで用意されているのが、パスワードリマインダです。
2. 秘密の質問に答えると、パスワードを再設定できるしくみです。
3. ところが、母親の旧姓や出身校といった答えは、SNSから調べられてしまいます。
4. どんなに強いパスワードでも、再設定の経路が甘ければそこから破られます。
5. 秘密の質問の答えも、他人に推測できない別のパスワードだと考えて決めます。

**P10 クイズ1**（s10・61字）
1. ここで問題です。
2. パスワードを使い回していると、とくに危ないのはどちらの攻撃でしょうか。
3. 正解は、パスワードリスト攻撃です。（考える間 1.8秒）

**P11 クイズ2**（s11・60字）
1. 次の問題です。
2. パスワードそのものをネットワークに流さない方式は、どちらでしょうか。
3. 正解は、チャレンジレスポンス認証です。（考える間 1.8秒）

**P12 クイズ3**（s12・51字）
1. 最後の問題です。
2. 総当たり攻撃に対して、より効くのはどちらでしょうか。
3. 正解は、文字数を長くすることです。（考える間 1.8秒）

**P13 まとめ**（s13・91字）
1. 利用者IDで名乗り、パスワードで本人だと確かめます。
2. パスワードの強さは長さで決まり、使い回しは避けます。
3. 流さないチャレンジレスポンス認証や、使い捨てのワンタイムパスワードで守ります。
4. （共通音声 OUTRO_SEG）
