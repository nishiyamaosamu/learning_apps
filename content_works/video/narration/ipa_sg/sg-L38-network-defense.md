## 用語の呼称（この回の正）

| 用語 | この回での言い方 |
|---|---|
| パケット | 通信が分かれて流れる小さな荷物。宛先・送信元・ポート番号という「荷札」が付く |
| ファイアウォール | 境界に置く関所。決めたルールで通すか止めるかを判定する（＝防火壁） |
| パケットフィルタリング | 荷札（宛先・送信元・ポート番号）だけを見て機械的に振り分ける方式 |
| DMZ | 社内でも外でもない緩衝地帯。外に公開するサーバだけを置く区画 |
| IDS | 通信を見張り、異常に気づいたら管理者に知らせる（侵入検知システム） |
| IPS | 見張ったうえで、その場で通信を遮断までする（侵入防止システム） |
| URLフィルタリング | 行き先のアドレスを見て、危険なサイトへのアクセスを止める |
| コンテンツフィルタリング | 通信の中身を見て判断する |

## L36 との突合（呼称の申し送り）

L36（アクセス制御とゼロトラスト）は「境界防御」という語を出さず、対比の左列を「これまでの守り方」と

**この回も「境界防御」という語は一度も使っていない。** 呼び方は
「社内と外との境目に置く関所」「境界に置く関所」で通し、そこに置く仕組みの名前
（ファイアウォール／DMZ／IDS・IPS／フィルタリング）だけを語っている。
（L36 の「これまでの守り方」＝この回の「境界の関所」を指す関係だが、どちらの回でも

## TTS 対策（音声側だけ仮名書き・字幕と画面は元の表記のまま）

DMZ→「ディーエムゼット」／ IDS→「アイディーエス」／ IPS→「アイピーエス」／ URL→「ユーアールエル」。
いずれも1字ずつ読む略語なので字幕に読みは添えない。仮名の前後は半角スペースで区切っている。

**「通す／通ります」→「とおす／とおります」**（v2 で追加）。v1 は s06-2「公開しているので通します」が
「つうします」と音読みされて差し戻された。この回は「通信」（音読みで正しい）が20文以上に出るので、
訓読みの「通す」が音読みへ引きずられやすい。**訓読みの『とおす』系は全セグメントをまとめて仮名に
揃える**（1本だけ直すと残りが漢字のまま＝同じ誤読が別の文で出る）。対象は次の4本:

| セグメント | 音声用テキスト（jobs.json） | 字幕・画面 |
|---|---|---|
| s04-1 | 必ず境界の一点を**とおります**。 | 通ります |
| s05-2 | 決めたルールでパケットを**とおすか**止めるかを判定します。 | 通すか |
| s06-2 | 公開しているので**とおします**。 | 通します |
| s15-1 | 荷札のルールで**とおすか**止めるかを決めます。 | 通すか |

「通信」は音読みなので漢字のまま。字幕に読みは添えない（漢字を見れば読めるため）。

## 原稿

### 2. intro
- s02-1 会社のパソコンは、いつもインターネットとつながっています。
- s02-2 便利な反面、その一本の道は、攻撃者にとっての入口でもあります。
- s02-3 そこで、社内と外との境目に関所を置いて、通信を見張ります。

### 3. packet
- s03-1 通信は、パケットと呼ばれる小さな荷物に分かれて流れています。
- s03-2 一つ一つのパケットには、荷札のような情報が付いています。
- s03-3 どこへ届けるかを示す宛先と、どこから来たかを示す送信元。
- s03-4 そして、どのサービス宛かを示すポート番号です。

### 4. boundary
- s04-1 社内と外をやり取りするパケットは、必ず境界の一点を通ります。
- s04-2 だからそこに関所を置けば、すべての通信を確かめられます。
- s04-3 アドレスやポート番号そのものの仕組みは、後のネットワークの章で学びます。

### 5. firewall
- s05-1 境界に置く関所が、ファイアウォールです。
- s05-2 防火壁という名のとおり、決めたルールでパケットを通すか止めるかを判定します。
- s05-3 見るのは荷札だけ。宛先や送信元、ポート番号で機械的に振り分けます。
- s05-4 この方式を、パケットフィルタリングといいます。

### 6. rules
- s06-1 実際のルールを見てみましょう。
- s06-2 外から社内のウェブサーバへの通信は、公開しているので通します。
- s06-3 外から社内のファイル共有への通信は、必要がないので止めます。
- s06-4 ルールに無い通信は、原則としてすべて止めるのが基本です。

### 7. dmz
- s07-1 困るのが、外に公開するサーバの置き場所です。
- s07-2 ウェブサーバやメールサーバは、外から使ってもらう必要があります。
- s07-3 でも社内ネットワークに置くと、外の通信を社内まで引き入れてしまいます。
- s07-4 そこで、社内でも外でもない緩衝地帯を作り、公開サーバだけをそこに置きます。
- s07-5 この区画が、DMZです。

### 8. dmz-case（★抽象→具体）
- s08-1 DMZが効くのは、公開サーバが乗っ取られたときです。
- s08-2 攻撃者がウェブサーバを乗っ取り、次に社内を狙ったとします。
- s08-3 しかし、DMZから社内への通信も、ファイアウォールが止めています。
- s08-4 被害を公開サーバだけに閉じ込める。これが、分けて置く理由です。

### 9. ids-ips
- s09-1 ルールをすり抜ける、怪しい通信もあります。
- s09-2 通信を見張り、異常に気づいたら管理者に知らせるのがIDSです。
- s09-3 日本語では、侵入検知システムといいます。
- s09-4 その場で通信を遮断までするのがIPS、侵入防止システムです。
- s09-5 検知のIDSと、防止のIPS。この一字が大きな違いです。

### 10. filtering
- s10-1 守るのは、外から中への通信だけではありません。
- s10-2 社内から外へ出ていく通信も、同じように制御します。
- s10-3 行き先のアドレスを見て、危険なサイトを止めるのがURLフィルタリングです。
- s10-4 通信の中身を見て判断するのが、コンテンツフィルタリングです。
- s10-5 行き先で見るか、中身で見るか。見ている場所が違います。

### 12〜14. クイズ（正解 A / B / A）
- s12-1 一問目です。ファイアウォールが見ているのは、どちらでしょうか。
- s12-2 正解は、宛先や送信元、ポート番号です。
- s12-3 荷札の情報だけを見て、機械的に振り分けていましたね。
- s13-1 二問目です。DMZに置くのは、どちらのサーバでしょうか。
- s13-2 正解は、外に公開するウェブサーバです。
- s13-3 社内だけで使うサーバは、社内ネットワークに置いたままにします。
- s14-1 三問目です。怪しい通信をその場で遮断するのは、どちらでしょうか。
- s14-2 正解は、IPS、侵入防止システムです。
- s14-3 IDSは、気づいて知らせるところまででしたね。

### 15. summary
- s15-1 今回のまとめです。ファイアウォールは、荷札のルールで通すか止めるかを決めます。
- s15-2 DMZは公開サーバを分けて置き、被害を社内まで広げません。
- s15-3 IDSは気づいて知らせ、IPSはその場で止めます。
- s15-4 そして、中から外への通信は、フィルタリングで見張ります。
