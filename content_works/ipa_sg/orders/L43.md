# SG-L43 メールのセキュリティ①：送信元ドメイン認証

- **一言で**: 「送信者は名乗り放題」への答え — 受信側がドメインの正当性を確かめる3つの仕組み
- **シラバス**: 情報セキュリティ#5「認証技術」のうち送信元ドメイン認証（SPF・DKIM・DMARC）
- **主担当**: なし（なりすましメールの攻撃側は L10＝完成済み。呼称は narration/ipa_sg/sg-L10-spoofing-phishing.md に揃える）
- **依存**: L10 の後（完成済み）。「送信者は偽装できる」は説明済みなので、対策側から入れる

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| 【前提】メール配送の仕組み | メールは送信側サーバから受信側サーバへ渡り、宛先の探索にDNSを使う。前提は最大2シーン（詳細はL62・L61へ） |
| なぜドメイン認証か | 差出人欄は自由に書けるので、見た目でなく「送ってきたサーバがそのドメインの正規のサーバか」を機械的に確かめる、が発想の転換 |
| SPF | 「うちのドメインのメールはこのサーバから送る」をDNSに宣言し、受信側が送信元と照合する（R5問6の題材） |
| DKIM | 送信側がデジタル署名を付け、受信側がDNS上の公開鍵で検証する。改ざんされていないことまで分かる（署名の仕組みはL17参照） |
| DMARC | SPF・DKIMの検証に失敗したメールをどう扱うか（受け取る・隔離・拒否）を送信側が宣言する。3つの関係を1枚の図で締める |

## 扱わない
- フィッシング・第三者中継など攻撃側の手口 → L10（完成済み、参照のみ）
- S/MIME・PGP（本文の暗号化）・SMTP-AUTH・OP25B・ベイジアンフィルタリング → L44
- SMTP・メールサーバの詳しい仕組み → L62、DNSの名前解決 → L61
- デジタル署名の仕組み → L17（参照のみ）

## 確認パート
- 通常クイズ2〜3問
- 出しどころ: SPFが照合するもの（送信元サーバ、R5問6の型）／SPF・DKIM・DMARCの役割の対応づけ
