# SG-L44 メールのセキュリティ②：暗号化とスパム対策

- **一言で**: 中身を守る（暗号化・署名）と、そもそも出させない・受け取らない（スパム対策）
- **シラバス**: 情報セキュリティ#5「認証技術」の残り（S/MIME・PGP・SMTP-AUTH・OP25B・ベイジアンフィルタリング）
- **主担当**: なし
- **依存**: L43 の後（メール配送の前提とドメイン認証は説明済み。この回は「それでも残る穴」から始める）

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| メールは平文で運ばれる | ドメイン認証（L43）を通っても中身は読める。本文を守るには暗号化が要る、が導入 |
| S/MIME | 証明書（L21）を使ってメール本文の暗号化とデジタル署名を行う標準方式 |
| PGP | 同じ目的を認証局なし（利用者同士の信頼）で実現する方式。S/MIMEとの違いは「誰が鍵を保証するか」 |
| SMTP-AUTH | 送信サーバが「送る前に利用者を認証する」。誰でも送信サーバを使える状態を塞ぐ |
| OP25B | プロバイダが外向きの25番ポートを塞ぎ、正規の送信サーバ経由を強制する。迷惑メールの大量送信を出口で止める |
| ベイジアンフィルタリング | 迷惑メールの特徴を統計的に学習して振り分ける。受信側の最後の網 |

## 扱わない
- SPF・DKIM・DMARC → L43（説明済み、参照のみ）
- 証明書・認証局の仕組み → L21、デジタル署名 → L17（参照のみ）
- 迷惑メール・フィッシングの手口 → L3・L10（完成済み、参照のみ）
- ポート番号の詳しい話 → L61、メール配送の仕組み → L62
- 特定電子メール法（法規制側）→ L52

## 確認パート
- 通常クイズ2〜3問
- 出しどころ: S/MIMEに必要なもの（証明書）／OP25Bが塞ぐもの／SMTP-AUTHのタイミング（送信時の認証）
