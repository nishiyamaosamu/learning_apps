# SG-L28 ISMS①：マネジメントシステム

- **一言で**: 守る活動を「回る仕組み」にする — JIS Q 27001が要求するPDCAの型
- **シラバス**: 情報セキュリティ#2「情報セキュリティマネジメントシステム（ISMS）」の前半（マネジメントシステムの要求事項。管理策と認証制度はL29へ）
- **主担当**: なし（リスクアセスメントの中身は L24 が正。この回は「ISMSが計画段階でそれを要求する」と接続するだけ）
- **依存**: L24・L25 の後（計画の説明でリスクアセスメント・リスク対応を既習として使う）

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| ISMSとJIS Q 27001（ISO/IEC 27001） | 個々の対策でなく「仕組み」の規格。要求事項を満たせば認証を受けられる（制度はL29） |
| ISMS適用範囲 | どの事業・拠点・情報を対象にするかを最初に区切る。全社一斉でなくてよい |
| リーダーシップ | 経営層が方針を定め、資源を割り当て、責任を持つ。現場任せではISMSと呼べない |
| 計画・運用 | リスクアセスメント（L24）とリスク対応（L25）を計画に組み込み、日常業務として運用する |
| パフォーマンス評価 | 内部監査とマネジメントレビュー。「決めたとおり動いているか」を自分たちで点検し、経営層が見直す |
| 改善（不適合・是正処置・継続的改善） | 見つかった不適合は原因まで遡って直す（是正処置）。回すたびに良くしていくのがゴール |

## 扱わない
- JIS Q 27002・管理策の4区分・管理策タイプ → L29
- ISMS適合性評価制度・ISMS認証・情報セキュリティガバナンス → L29
- 内部監査とシステム監査の違い → L70（第8章）
- 監査指摘への改善計画のケース演習 → L96（科目B）

## 確認パート
- 通常クイズ2〜3問
- 出しどころ: PDCAの各段階と用語の対応（内部監査はCheck）／不適合への是正処置は「原因の除去」まで／リーダーシップの主体は誰か
