# SG-L70 システム監査

- **一言で**: 自分で「できている」と言っても信用されない — 独立した目で検証して初めて証明になる
- **シラバス**: 中分類8「システム監査の目的と手順」「情報セキュリティ監査」「コンプライアンス監査」
- **主担当**: なし（ISMSの内部監査は L28 で説明済み。関係を整理する側）
- **依存**: L28 の後（内部監査という言葉を既習として、監査の一般論に広げる）

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| システム監査の目的 | 情報システムが正しく・安全に・効率よく使われているかを、利害のない第三者の目で検証・評価する |
| 監査人の独立性と客観性 | 監査される部門から独立していること。自分の作ったものを自分で監査してはいけない、が核 |
| 監査の手順 | 計画→実施→報告→フォローアップの4ステップ（R8問8の題材）。指摘して終わりでなく、改善されたかまで見る |
| 監査証拠 | 「見た・聞いた」でなく記録で裏づける。ログ（L37）・台帳（L23）が監査証拠になる、と既習に接続 |
| 情報セキュリティ監査基準／管理基準 | 監査人の行動規範（監査基準）と、チェック項目集(管理基準)の使い分け（R5問1の題材） |
| コンプライアンス監査 | 法令・行動指針の順守状況を見る監査。第6章の法律群が「守れているか」を確かめる仕組み、と章をまたいで束ねる |

## 扱わない
- 内部統制の仕組み（職務分掌・統制活動）→ L71（次回。監査が「見る対象」の側）
- ISMSの内部監査・マネジメントレビュー → L28（説明済み、参照のみ）
- 監査指摘への改善計画のケース演習 → L96（科目B）
- 会計監査・財務諸表 → L77（範囲外につき名前も出さない）

## 確認パート
- 通常クイズ2〜3問
- 出しどころ: 監査人の独立性が崩れる例の判別（R8問8の型）／監査基準と管理基準の違い（R5問1の型）／フォローアップの意味
