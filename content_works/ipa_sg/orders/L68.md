# SG-L68 サービスマネジメント②：サービスの運用

- **一言で**: 毎日サービスを回す現場 — 問合せ・障害・根本原因、それぞれ別の管理で受ける
- **シラバス**: 中分類7「サービスの運用」「インシデント管理・サービス要求管理・問題管理」「資産管理・構成管理」
- **主担当**: なし。**L30（情報セキュリティのインシデントハンドリング）と同名の別概念であることに必ず触れる**（L30側でも予告済み）
- **依存**: L67 の後（SLAを守るための日々の運用、という接続）。L30 の後（用語の区別を双方向にするため）

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| サービスデスクと運用オペレーション | 利用者の窓口（サービスデスク）と、裏で回る監視・操作・作業指示書・操作ログ。運用は記録で回る |
| インシデント管理 | サービスの中断を**とにかく早く復旧させる**管理。応急処置（回避策）でよい、が要点。**L30のセキュリティインシデントハンドリングとは別概念**、と正面から区別する |
| サービス要求管理とエスカレーション | 「パスワードを初期化して」など通常の依頼はインシデントと分けて受ける。手に負えないものは上位へエスカレーション |
| 問題管理 | 繰り返すインシデントの**根本原因**を探して恒久対策する管理。既知の誤り・傾向分析をここで。「早く戻す」と「二度と起こさない」の分業 |
| 重大なインシデントとヒヤリハット | 経営に響く障害は特別扱い。事故未満のヒヤリハットも記録して問題管理の材料にする |
| 資産管理・構成管理 | 何を持ち（資産・ライセンス）、どうつながっているか（構成品目：CI）。構成が分からないと影響範囲が読めない — L37のSBOMと同じ発想と一言 |

## 扱わない
- セキュリティ側のインシデントハンドリング（トリアージ・CSIRT）→ L30（説明済み。区別の場面で対比するのみ）
- 変更管理・リリース及び展開管理・移行 → L69
- SLA・サービスレベル目標 → L67（説明済み、参照のみ）
- ライセンス違反の法的側面 → L47・L53（参照のみ）

## 確認パート
- 通常クイズ2〜3問
- 出しどころ: インシデント管理と問題管理の目的の違い（定番）／L30との使い分け／サービス要求とインシデントの判別
