# SG-L46 アプリケーションセキュリティ

- **一言で**: L8・L9で見た攻撃は、作る側の「作法」でほぼ防げる — セキュアプログラミングの基本
- **シラバス**: 情報セキュリティ#5「アプリケーションセキュリティ」全部（データベースセキュリティはL58へ）
- **主担当**: なし（攻撃側の正は L8・L9＝完成済み。SQL・XSSなどの読みの扱いも narration/ipa_sg/sg-L8・sg-L9 に揃える）
- **依存**: L8・L9 の後（完成済み）。攻撃の再説明はせず「あの攻撃にはこの対策」の対で構成する

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| セキュアプログラミング | 攻撃されることを前提に書く作法の総称。「入力は全部疑う」が合言葉 |
| SQLインジェクション対策：プレースホルダ | 命令文と入力データを最初から分けて渡すので、入力に何を書かれても命令にならない（R5問7の題材）。L8の攻撃と対 |
| クロスサイトスクリプティング対策：エスケープ | 画面に出す前に特別な文字を無害な表記に変換する。入力チェックとの二段構えで。L9の攻撃と対 |
| バッファオーバーフロー対策 | 入力の長さを検査してから領域に入れる。あふれさせない、の一言で。L8の攻撃と対 |
| 対策の置き場所 | 対策はアプリを作る側の実装に入れるのが本筋で、WAF（L39）は外側の保険 — 二重の守りとして整理 |

## 扱わない
- SQLインジェクション・XSS・CSRF・バッファオーバーフローの攻撃の仕組み → L8・L9（完成済み、参照のみ）
- WAFの製品説明 → L39（説明済み、参照のみ）
- データベースの暗号化・アクセス制御・ログ取得 → L58
- CSRF対策・セッション管理の実装詳細 → シラバス用語例にないため深入りしない（「同じ発想で防ぐ」と一言のみ）

## 確認パート
- 通常クイズ2〜3問
- 出しどころ: プレースホルダが効く理由（R5問7の型）／エスケープはどの攻撃への対策か／対策を実装に入れる意味
