# SG-L66 プロジェクトマネジメント

- **一言で**: 「いつも」と違う仕事＝プロジェクトを、憲章・関係者・範囲・段取りで管理する地図
- **シラバス**: 中分類6「プロジェクトマネジメント」全体【地図＋代表】
- **主担当**: なし（プロジェクトのリスク対応の用語は L25 が正＝説明済み。参照する）
- **依存**: なし（第8章の入口）

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| プロジェクトの特性 | 定常業務と違い「独自の成果物・明確な期限・有期の体制」。セキュリティ対策の導入もプロジェクト、と自分事に |
| プロジェクト憲章 | プロジェクトの存在を公式に認める文書。目的・体制・権限をここで与える |
| ステークホルダ | 影響を受ける・与える関係者を最初に特定してマネジメントする。「後から出てくる反対者」を防ぐ |
| スコープとWBS | やる範囲を決め（スコープ）、作業に分解する（WBS）。「やらないことを決める」のがスコープの本質 |
| PERT | 作業の順序と所要日数から、遅らせられない経路（クリティカルパス）を見つける。図1枚を読み解く1シーンで |
| 対象群の地図（1シーン） | リスク・品質・調達・コミュニケーション・資源・時間・コストという管理の引き出しを1枚で。リスク対応の用語はL25の4分類を参照。網羅は暗記カード |

## 扱わない
- 資源・時間・コスト・統合・品質・調達・コミュニケーションの各対象群の詳細用語（ベースライン・プッシュ型/プル型など）→ 暗記カード
- リスク対応の4分類の定義 → L25（説明済み、参照のみ）
- 要件定義・調達（RFPなど発注側の流れ）→ L73
- 開発工程・テストの話 → シラバス範囲外につき扱わない
