# SG-L18 パスワードによる認証

- **一言で**: L7の攻撃に対して、パスワードを「作る・送る・預ける」それぞれで守る
- **シラバス**: 情報セキュリティ#1「情報セキュリティ技術（利用者認証）」のうちパスワード関連＋「認証技術」のチャレンジレスポンス認証
- **主担当**: なし（パスワードを狙う攻撃の正は L7＝完成済み。攻撃名の呼称は narration/ipa_sg/sg-L7-password-attacks.md に揃える）
- **依存**: L7 の後（攻撃側は説明済み。この回は対策側で、攻撃の再説明はしない）

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| ログインとアクセス管理 | 利用者IDが「誰か」を名乗り、パスワードが「本人か」を確かめる。認証の基本形 |
| パスワード強度 | 総当たり（L7）に効くのは長さ。短くて複雑より長い方が強い、を桁の話で |
| 使い回し対策 | パスワードリスト攻撃（L7）はどれだけ強いパスワードでも使い回した瞬間に破られる。サービスごとに変えるが唯一の対策 |
| チャレンジレスポンス認証 | パスワードそのものをネットワークに流さない工夫。毎回変わる「お題」に計算で答える |
| ワンタイムパスワードとセキュリティトークン | 一度きりで使い捨てるので、盗まれても次は使えない。トークンは生成する道具 |
| パスワードリマインダの注意点 | 「秘密の質問」の答えはSNSから調べられる。再設定経路が最弱リンクになる話 |

## 扱わない
- 辞書攻撃・総当たり・リバースブルートフォース・パスワードリスト攻撃の仕組み → L7（完成済み、名前を出して参照するだけ）
- 多要素認証・多段階認証・パスワードレス認証（FIDO）・シングルサインオン → L19
- 生体認証・ICカード・PINコード → L20
- アカウント管理・アクセス権の管理（管理者側の統制） → L22・L36

## 確認パート
- 通常クイズ2〜3問
- 出しどころ: 使い回しがなぜ危険か（リスト攻撃との対応）／チャレンジレスポンス認証が防ぐこと（パスワードを流さない）
