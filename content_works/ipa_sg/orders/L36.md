# SG-L36 アクセス制御とゼロトラスト

- **一言で**: 「誰に何をどこまで許すか」を仕組みで強制する — そして「中なら信用する」をやめる
- **シラバス**: 情報セキュリティ#4「技術的セキュリティ対策」のうちアクセス制御・アクセス権の設定・特権的アクセス権の管理・検疫ネットワーク（＋LESSON_PLANの指定でセキュアOS・ゼロトラスト）
- **主担当**: ★ アクセス制御・最小権限。L22（説明済み・参照元）・L83・L88（科目B）が参照する
- **依存**: なし（L22が地図として一言触れた「最小権限」を、この回が運用のレベルに落とす。呼称はL22に揃える）

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| アクセス制御とアクセス権の設定 | 利用者・グループごとに読む/書く/実行するを割り当てる。need-to-know（最小権限）を権限表のレベルで具体化する |
| アクセス権の見直し | 権限は貯まる一方になりがち。異動・退職のたびに棚卸しする（L88のケース演習の下敷き） |
| 特権的アクセス権の管理 | 管理者権限は「何でもできる」ので、人を限定し・共有せず・操作を記録する |
| セキュアOS | 強制アクセス制御と管理者権限の分離で「管理者でも何でもはできない」OS（R8問6の題材） |
| ゼロトラスト | 「社内ネットワークの中なら信用する」をやめ、アクセスのたびに検証する考え方。境界防御（L38）との対比で |
| 検疫ネットワーク | つなぐ前に検査する。持ち込みPCをいきなり社内LANに入れず、隔離網で健全性を確かめてから通す |

## 扱わない
- アカウント管理の組織側手続（割当て・誓約書）→ L34（参照のみ）
- 認証の技術（パスワード・多要素）→ L18・L19（完成予定の第2章、参照のみ）
- ファイアウォール・DMZなど境界防御の仕組み → L38
- データベースのアクセス制御 → L58
- SaaS認証設定のケース演習 → L83、アクセス権見直しのケース演習 → L88（科目B）
