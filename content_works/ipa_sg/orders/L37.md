# SG-L37 ログ管理と脆弱性管理

- **一言で**: 記録がなければ調べられない、穴を塞がなければ守れない — 地味だが効く2つの日常運用
- **シラバス**: 情報セキュリティ#4「技術的セキュリティ対策」のうちログ管理・ネットワーク監視・脆弱性管理（OSアップデート・セキュリティパッチ・SBOM）
- **主担当**: ★ ログ管理（種類・取得目的・保持）。L58・L87（科目B）が参照する
- **依存**: なし

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| ログの種類と取得目的 | 認証ログ・操作ログ・通信ログなどを「何のために取るか」とセットで。目的なく取ったログは調べるとき使えない |
| ログの記録・分析・保持 | 取る→定期的に見る→決めた期間残す。「取っているが誰も見ていない」が実務の典型的な穴（L87の下敷き） |
| ネットワーク監視 | 通信の流れを常時見て異常に気づく。ログ（事後に調べる）と監視（リアルタイムに気づく）の対で |
| 脆弱性管理 | OSアップデートとセキュリティパッチの適用。放置された既知の穴が侵入口の定番（ゼロデイ（L12）とは逆の「既知なのに」問題） |
| SBOM | ソフトの部品表。自社システムにどの部品が入っているか分からないと、脆弱性が公表されても影響を判断できない |
| パッチ適用基準 | すぐ当てられない事情（業務停止・互換性）があるとき、何日以内・どの深刻度から当てるかを決めておく（L88の下敷き。深刻度はL33のCVSSを参照） |

## 扱わない
- ログを集約・相関分析する製品（SIEM）→ L39
- 侵入検知の仕組み（IDS/IPS）→ L38
- 脆弱性の深刻度評価（CVSS）→ L33（参照のみ）
- データベースのログ取得 → L58
- ログ監視のケース演習 → L87、パッチ適用基準のケース演習 → L88（科目B）

## 確認パート
- 通常クイズ2〜3問
- 出しどころ: ログを取る目的（事後調査・不正の抑止）／SBOMが役立つ場面／パッチをすぐ当てられないときに決めておくこと
