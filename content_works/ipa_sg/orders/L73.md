# SG-L73 システム企画と調達

- **一言で**: システムは「作る前」で決まる — リスクを読み、要件を書き、正しく発注する
- **シラバス**: 中分類10「システム化計画」「要件定義」「調達計画・実施」＋中分類9「情報システム廃棄」
- **主担当**: なし（リスク対応の用語は L25 が正＝説明済み。参照する）
- **依存**: L25 の後（システム化計画のリスク分析でL25の用語を使う）。L53 の後が望ましい（契約形態を既習として調達に進める）

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| システム化計画のリスク分析 | 導入で何が起こり得るか（発生頻度・影響・範囲）を先に読む。対応の考え方はL25の4分類を参照 |
| 要求分析と要件定義 | 現場の声を集めて分析し、要件として文書に固める。「言われたとおり」と「本当に必要」のずれを埋める工程 |
| 機能要件・非機能要件・セキュリティ要件 | 何ができるか（機能）と、速さ・可用性・保守性（非機能）。**セキュリティ要件は非機能の代表で、後付けできない**が回の芯 |
| RFI・RFP・RFQ | 情報をください→提案をください→見積りをください、の3段階。順番と役割を1枚の流れ図で |
| 調達選定と契約締結 | 提案評価基準で公平に選び、役割分担を契約に落とす。契約形態（準委任/請負）はL53を参照 |
| システムライフサイクルと廃棄 | 導入から廃棄までが企画の視野。データの消去（CE＝L40参照）・機器の廃棄（L41参照）で章をまたいで回収 |

## 扱わない
- 準委任契約・請負契約・開発委託モデル契約の中身 → L53（説明済み、参照のみ）
- リスク対応4分類の定義 → L25（説明済み、参照のみ）
- 委託先の事前調査・監督のケース演習 → L89（科目B）
- 外部資源の利用（システムインテグレータ・SI事業者・アウトソーシング）→ 暗記カード（調達の導入で名前に触れる程度）
- プロジェクトとしての実行管理 → L66（説明済み、参照のみ）

- 通常クイズ2〜3問
- 出しどころ: RFI・RFP・RFQの順序と役割（定番）／セキュリティ要件を要件定義段階で書く理由
