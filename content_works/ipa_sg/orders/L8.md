# SG-L8 Webを狙う攻撃①：入力をだます

- **一言で**: 入力欄に「データのつもりでない文字」を入れられると、サーバが命令として実行してしまう
- **シラバス**: 情報セキュリティ#1「サイバー攻撃手法」（インジェクション系）
- **主担当**: なし。対策側（プレースホルダ・エスケープ）の正は L46
- **依存**: なし。**L46 と対になる回**で攻撃側だけを担当。L9 とは「サーバを狙う／利用者を狙う」で分担

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| 【前提】HTTPとWebアプリの仕組み | ブラウザが送った入力をサーバのプログラムが受け取って処理する、という1枚だけ。**最大2シーン**。詳しい仕組みは L63 |
| SQLインジェクション | 入力がデータベースへの命令の一部になってしまう。**この回の主役**として一番丁寧に |
| OSコマンドインジェクション | 同じ理屈でサーバのOSコマンドが実行される。SQLとの共通構造を示す |
| ディレクトリトラバーサル | パスをさかのぼって、見せるつもりのないファイルを読まれる |
| バッファオーバーフロー | 想定より長いデータで領域があふれ、隣の領域が上書きされる |
| 共通する原因 | すべて「入力を信用した」こと。だから対策も共通、と L46 へ渡す |

## 扱わない
- 対策（プレースホルダ・エスケープ・入力検証）→ L46
- 利用者側を狙う攻撃（XSS・CSRF ほか）→ L9
- HTTP・cookie・URL の詳しい仕組み → L63
- 脆弱性診断・ファジング → L33
