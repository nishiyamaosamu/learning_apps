# SG-L33 セキュリティ評価

- **一言で**: 攻撃者より先に自分の弱点を知る — 弱点の「深刻さ」を共通の物差しで測る
- **シラバス**: 情報セキュリティ#3「セキュリティ評価」全部（＋LESSON_PLANの指定でホワイト/ブラックボックス検査・ファジングまで）
- **主担当**: なし
- **依存**: なし（第4章の入口。「対策の前にまず測る」で章を開ける）

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| CVSS（共通脆弱性評価システム） | 脆弱性の深刻さを0〜10で共通化する物差し。「うちのシステムでは何点か」まで含めて評価できる |
| CVSSの3つの評価基準 | 基本（脆弱性そのもの）・現状（攻撃の出回り具合で変わる）・環境（自社での影響）。時間と場所で点が変わる、が肝 |
| 脆弱性診断 | ツールや専門家が既知の弱点を網羅的に洗い出す健康診断 |
| ペネトレーションテスト | 実際に侵入を試みる実地試験。診断（弱点のリストアップ）との違いは「目的を達成できてしまうか確かめる」こと |
| ホワイトボックス／ブラックボックス検査 | 内部情報を知らせて検査するか、外部の攻撃者と同じ条件でやるか |
| ファジング | 想定外のデータを大量に流し込んで異常を見つける。IoT機器や自作ソフトの検査で有効 |

## 扱わない
- 脆弱性が見つかった後の管理（パッチ適用・SBOM）→ L37
- レッドチーム演習（人と組織を試す訓練）→ L34。ペネトレーションテストとの違いに一言だけ触れて渡す
- エシカルハッカー → L30（参照のみ）
- JVN・早期警戒パートナーシップ（脆弱性情報の流通）→ L31（参照のみ）
