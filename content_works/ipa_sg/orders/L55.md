# SG-L55 システム構成とクラウド

- **一言で**: 処理はどこでやるか・機械はどこにあるか — そしてクラウドでは「どこまでが自分の責任か」
- **シラバス**: 中分類3「システムの構成」のうち処理形態・システム構成（仮想化・クラウド）＋中分類9「ソリューションビジネス」＋情報セキュリティ#4「クラウドサービスのセキュリティ」【地図＋代表】
- **主担当**: ★ クラウドの責任共有モデル（L22＝説明済みの参照元・L83・L90・L91が参照）
- **依存**: なし（L22が一言触れた責任共有モデルをこの回が本格的に定義する。呼称はL22に揃える）

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| 集中処理／分散処理と処理形態の地図（1シーン） | 1台に集めるか複数で分けるか、バッチ／リアルタイムなどの利用形態。地図として一気に通過する |
| クライアントサーバシステムとシンクライアント | 役割分担の基本形と、端末に何も残さない構成。端末に残さない＝盗難時に漏れない、とセキュリティに接続 |
| 仮想化（VM・VDI） | 1台の物理マシンに複数の仮想マシン。VDIは「デスクトップごとサーバ側に置く」でシンクライアントとつながる |
| クラウドコンピューティング（SaaS・PaaS・IaaS） | 何を借りるかの3段階。アプリごと／開発環境まで／土台だけ、を積み木の絵で |
| エッジコンピューティング | クラウドと逆向きの発想。現場の近くで処理して遅延を減らす |
| 責任共有モデル（主担当） | SaaS/PaaS/IaaSごとに事業者と利用者の責任の線が動く。**設定ミス・認証・ログは常に利用者の責任**、まで言い切る |

## 扱わない
- ピアツーピア・ASP・ソブリンクラウド・対話型処理・機能配分などの用語 → 暗記カード（地図で名前だけ）
- 冗長構成・デュアル/デュプレックス・RAID・信頼性設計 → L57
- Webシステムの仕組み → L63
- クラウドの可用性評価・利用リスク評価のケース演習 → L90・L91（科目B）、SaaS認証設定 → L83（科目B）

- 出しどころ: SaaS/PaaS/IaaSの判別（借りる範囲）／SaaSでも利用者の責任に残るもの（設定・認証・ログ）
