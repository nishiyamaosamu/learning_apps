# 発注書（orders/）

動画1本ぶんの**範囲を先に確定させた指示書**。`<L番号>.md` の1ファイル＝1本。

制作エージェントはこれと `.claude/skills/create-learning-video/SKILL.md` だけを読めば
シナリオを書き始められる（LESSON_PLAN 全体・シラバス全文を毎回読ませない）。

## なぜ先に作るのか

1. **範囲の判断を制作から切り離す** — 「どこまで語るか」は隣のレッスンとの兼ね合いで決まるので、
   1本だけ見ているエージェントには決められない。章単位でまとめて切ると重複と穴が同時に潰せる
2. **読む量を減らす** — 制作側が読むのは20〜30行。毎回シラバス（588行）を漁らない
3. **範囲が記録に残る** — 後から「なぜこの用語を入れなかったか」を追える

## いつ作るか

**章単位で、その章の制作に入る直前に作る**。96本ぶんを最初に全部書かない
（作りながら方針が変わるので、遠い章の発注書は必ず陳腐化する）。

すでに完成している回（QUEUE.md が `review` / `done`）の発注書は作らない。
その回の範囲は `content_works/video/narration/<app>/<id>.md`（完成シナリオ）が事実上の記録になる。

## 作り方

章の全レッスンを**一度にまとめて**起こす。1本ずつ作ると隣との重複が見えない。

読むもの:
- `LESSON_PLAN.md` のその章の表（全行。隣のレッスンとの境界を引くため）
- `syllabus_sg_ver4_1.md` の対応する中分類（用語例の原文）
- 科目B（第9章）は `sg_koukai_mondai.md` の対応する出題型
- LESSON_PLAN の「用語の主担当」節（★の回はどこで定義するかが決まっている）

書き終えたら章全体を並べて確認する:
- 同じ用語が2本の「扱う」に入っていないか（入るなら片方は「扱わない」へ）
- シラバスの用語例で、その章のどの本にも入っていない語がないか
  （意図的に暗記カードへ委譲するなら「扱わない」に理由つきで書く）

## 書式

```markdown
# SG-L5 ランサムウェアとボットネット

- **一言で**: （この回のメッセージを一文で）
- **シラバス**: （対応する項目名）
- **主担当**: （★ならその用語。なければ「なし」＋定義の正がどの回か）
- **依存**: （先に作られているべき回と、その理由。なければ「なし」）

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| … | …（一言の定義か、身近な例。ここに書いた語は全部説明する） |

## 扱わない
- …（隣のどの回に渡すか、または暗記カード委譲かを必ず書く）

## 確認パート
- （通常クイズ / ケース問題のどちらか。出しどころの候補を1〜2行）
```

- 「扱う」は**5〜7項目まで**。それ以上はレッスンを分けるべき（LESSON_PLAN 側の問題として報告する）
- 用語は並べるだけにしない。「何を語るか」が書けない用語は、その回では扱わない
- 発注書はレイアウトや絵の指示をしない（それは制作側の工程3の仕事）
