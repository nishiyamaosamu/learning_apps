# SG-L2 情報資産・脅威・脆弱性

- **一言で**: 守る対象（情報資産）に、外からの力（脅威）が、弱点（脆弱性）を突いたときに事故が起きる — セキュリティの基本の三点セット
- **シラバス**: 情報セキュリティ#1「情報セキュリティの重要性」「脅威」「脆弱性」
- **主担当**: なし。ただし**この3語の関係の説明はこの回が事実上の入口**なので、以降の回はここの言い方に揃える
- **依存**: L1（CIA・多層防御）の後

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| 情報資産 | 守るべきものは「データ」だけではない（紙・機器・人の知識・評判も資産）。身近な例で |
| 脅威 × 脆弱性 = リスク | 3語の関係を一枚の絵で。脅威だけでも脆弱性だけでも事故にならない、が核心 |
| 脅威の種類の地図 | 大きく〔環境的〕事故・災害・故障 と〔人為的〕故意・過失 に分かれる、という分類だけ。個々の攻撃名は挙げない |
| バグ・セキュリティホール | 作り込まれた技術的な弱点。修正されるまでの時間が危ない |
| 人的脆弱性 | 弱点は人にもある（忙しさ・思い込み・悪意）。L3への橋渡し |
| シャドーIT | 会社が把握していないIT利用。「見えていない資産」は守れない |
| 事故が事業に与える影響 | 情報が漏れる以上に、事業が止まることが痛い。事業継続への脅威という視点。裏返して、セキュリティ水準の高さは企業の評価を上げる（守りはコストだけではない）まで一言 |

## 扱わない
- 個々の攻撃手法（ソーシャルエンジニアリング → L3、マルウェア → L4・L5、サイバー攻撃 → L7〜L14）
- 情報資産の重要度による分類・情報資産台帳の作り方 → L23（科目Bの実践は L79）
- リスクの算定・評価 → L24
- 内部統制の不備 → L71
- 脅威の語の網羅（破壊・盗難・侵入・不正アクセス・クラッキング・アクセス権の誤設定・誤謬・妨害行為など）
  → **この回は分類の地図だけを示し、語の網羅は暗記カードへ委譲**（画面に用語を並べない）
