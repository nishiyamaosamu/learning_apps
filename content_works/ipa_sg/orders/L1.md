# SG-L1 情報セキュリティとは

- **一言で**: 守るとは「使えなくすること」ではない — CIAのバランスと、設計段階から守る発想
- **シラバス**: 情報セキュリティ#1「情報セキュリティの目的と考え方」全部＋「重要性」の導入部分
- **主担当**: なし（シリーズ全体の入口。CIA＋4特性・多層防御の呼称はこの回が正で、L13（多層防御）・L17（真正性・否認防止）が参照する）
- **依存**: なし（全96本の1本目。作り直しの際は、参照側の完成回が使っている呼称——多層防御はL13、否認防止はL17の言い回し——を壊さないこと）

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| なぜ情報セキュリティか | 事故が事業の継続と企業の評価を左右する時代、という動機づけ。「うちは狙われない」の否定から入る |
| 機密性・完全性・可用性（CIA） | 見られない・書き換えられない・使いたいときに使える。3つは綱引きの関係（厳しくすると使いにくい）まで |
| 真正性・責任追跡性・否認防止・信頼性 | 追加の4特性を一言ずつ。本人か・誰がやったか辿れるか・後から否定できないか・意図どおり動くか |
| 多層防御 | 1枚の壁で守り切れる前提を捨て、入口・内部・出口に層を重ねる。以降の全レッスンの配置図になる考え方 |
| セキュリティバイデザイン／プライバシーバイデザイン | 後付けでなく企画・設計の段階から組み込む。L73（セキュリティ要件）への長い伏線 |

## 扱わない
- 情報資産・脅威・脆弱性の定義 → L2（次回。「守る対象と敵の話は次回」と予告で締める）
- 具体的な攻撃手法 → L3〜L14
- 暗号・認証などの守る技術 → 第2章
- ISMS・管理の仕組み → 第3章（L22・L28）

- 通常クイズ2〜3問
