# SG-L26 情報セキュリティ継続

- **一言で**: 事故は起きる前提で「それでも業務を止めない・戻せる」準備をしておく
- **シラバス**: 情報セキュリティ#2「情報セキュリティ継続」全部
- **主担当**: なし（バックアップ方式（フル/差分/増分・世代管理）の正は L59。この回は「対策としてのバックアップ」の位置づけまで）
- **依存**: なし（L2の「事故が事業継続にもたらす影響」を導入で回収すると入りやすい）

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| 緊急事態の区分 | 災害・障害・攻撃など、何が起きたかで動き方が変わる。区分を決めておくのが初動の速さになる |
| 緊急時対応計画（コンティンジェンシー計画） | 緊急事態が起きた直後に「誰が・何を・どの順で」やるかを事前に決めた計画 |
| 復旧計画（災害復旧・障害復旧） | 応急対応のあと、元の状態に戻すまでの計画。対応と復旧は別フェーズ、が整理の軸 |
| バックアップによる対策 | 戻すためにはデータの控えが要る。取ってあるだけでなく「戻せるか」の確認まで（方式・世代管理の詳細はL59へ） |
| 被害状況の調査手法 | 何がどこまでやられたかを把握してから戻す。順序を誤ると被害を広げる |

## 扱わない
- フルバックアップ／差分／増分・世代管理・リストア時間の計算 → L59（第7章）。この回では方式名に踏み込まない
- BCP・BCM・事業影響度分析（BIA） → L74（第8章）。「事業全体の継続はマネジメントの章で」と一言添える
- RTO・RPO・RLO・スタンバイ構成 → L69（第8章）
- インシデントハンドリングの流れ（検知→トリアージ→…） → L30
- バックアップ運用・復旧要件のケース演習 → L84・L85（科目B）

- 出しどころ: コンティンジェンシー計画は「いつ」のための計画か／対応と復旧の区別／バックアップは「戻せて初めて対策」
