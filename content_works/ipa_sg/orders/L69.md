# SG-L69 サービスマネジメント③：可用性と継続

- **一言で**: 「いつまでに・どの時点へ・どこまで」戻すか — 復旧目標の3点セットと備えの型
- **シラバス**: 中分類7「サービス可用性管理・サービス継続管理」「変更管理・サービスの設計及び移行・リリース及び展開管理」「容量・能力管理」「ファシリティマネジメント」
- **主担当**: ★ RTO・RPO・RLO・スタンバイ構成（L59＝説明済みの参照元・L85が参照）
- **依存**: L59 の後（バックアップ方式・リストア時間は既習。「その計算をRTO/RPOという目標に接続する」のがこの回）。第9章 L85 より先に作る

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| サービス可用性管理と継続管理 | 日常の「止めない」管理と、災害級の「それでも続ける・戻す」管理。L26（情報セキュリティ継続）のサービス版と接続 |
| RTO・RPO・RLO（主担当） | いつまでに（時間）・どの時点のデータへ（時点）・どのレベルまで（水準）。3つを1本の時間軸の図で定義する。L59のリストア時間計算がRTO充足の判定だった、と回収 |
| コールドスタンバイ／ホットスタンバイ | 予備を用意だけしておくか、常に同期して即切替か。復旧の速さとコストの対比（デュプレックス（L57）との関係も一言） |
| 変更管理・リリース及び展開管理・移行 | 本番を変えるときの承認・展開・切替の手続。「障害の多くは変更のあとに起きる」が動機。移行リハーサルまで |
| 容量・能力管理としきい値 | CPU・ディスク・回線の使用率を監視し、しきい値超えで先手を打つ。「足りなくなってから」では遅い |
| ファシリティマネジメント | 電気・空調など設備側の管理。UPS・耐震耐火（L41）をサービス継続の文脈で回収 |

## 扱わない
- バックアップの方式・世代管理・リストア時間の計算 → L59（説明済み、参照のみ）
- BCP・BCM・BIA（事業全体の継続）→ L74（「サービスより広い話は次々回」と予告）
- RAID・クラスタなど冗長構成の技術 → L57（説明済み、参照のみ）
- 復旧要件判断のケース演習 → L85（科目B、R6問14・R8問14型）

## 確認パート
- 通常クイズ2〜3問
- 出しどころ: RTO/RPO/RLOの判別（「4時間以内に」＝RTO、「前日夜の状態へ」＝RPO）／ホットスタンバイを選ぶ条件
