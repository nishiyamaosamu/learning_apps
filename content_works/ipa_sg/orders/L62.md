# SG-L62 メールの仕組み

- **一言で**: メールは「送る・貯める・取りに行く」の分業 — 仕組みが分かれば攻撃も対策も腑に落ちる
- **シラバス**: 中分類5「ネットワーク応用（電子メール）」＋「通信プロトコル（SMTP・POP3・IMAP）」
- **主担当**: なし（L43の【前提：メール配送】が参照してきた本丸。呼称はL43に揃える）
- **依存**: L61 の後（DNSを既習として、宛先サーバの探索を一言で済ませられる）

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| SMTPとリレー方式 | 送信と、サーバからサーバへの中継はSMTP。第三者中継（L10）・OP25B（L44）がこの仕組みの話だったと回収 |
| POP3とIMAP | 受信箱から「端末に取り込む」か「サーバに置いたまま読む」か。複数端末時代はIMAP、の対比で |
| cc・bcc・同報メール・メーリングリスト | 宛先の見え方の違い。**bccにすべき一斉送信をccでやる事故**が定番の情報漏えい、と実務に接続 |
| MIME | 文字しか運べなかったメールに添付ファイルや日本語を載せる拡張。S/MIME（L44）の「MIME」がこれ |
| HTMLメールの注意 | 見た目が作れる分、偽装リンクを隠せる（フィッシング（L10）の温床）。テキスト表示という自衛策まで |
| Webメール | ブラウザで読むメール。端末に残らない一方、パスワードが破られたらどこからでも読まれる |

## 扱わない
- SPF・DKIM・DMARC → L43、S/MIME・PGP・SMTP-AUTH・OP25Bの内容 → L44（説明済み、参照のみ）
- フィッシング・ビジネスメール詐欺の手口 → L3・L10（完成済み、参照のみ）
- メール誤送信の点検・持出し管理のケース演習 → L87（科目B）
- DNSの仕組み → L61（説明済み、参照のみ）

## 確認パート
- 通常クイズ2〜3問
- 出しどころ: 送信と受信のプロトコルの対応（SMTP／POP3・IMAP）／bccを使うべき場面（定番）
