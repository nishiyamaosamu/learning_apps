# SG-L16 ハッシュ関数と鍵管理

- **一言で**: 「戻せない変換」で改ざんを見抜く — そして暗号は永遠に安全ではない
- **シラバス**: 情報セキュリティ#1「情報セキュリティ技術（暗号技術）」の後半（暗号方式そのものはL15が担当済み）
- **主担当**: なし（暗号方式の正は L15。メッセージダイジェストの定義はこの回が正で、L17 が参照する）
- **依存**: L15 の後（平文・暗号文・鍵の用語、共通鍵／公開鍵の対比を前提に話す。呼称は narration/ipa_sg/sg-L15-encryption.md に揃える）

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| ハッシュ関数（SHA-256） | どんな長さの入力からも固定長のメッセージダイジェストを作る。暗号化と違い「鍵がなくても戻せない」のではなく**そもそも戻す仕組みがない** |
| 一方向性 | ダイジェストから元データを復元できない。パスワードを平文で保存しない話につなげる |
| 衝突困難性 | 同じダイジェストになる別データを作れない。だから「ダイジェストが一致＝中身が同じ」と言え、改ざん検知に使える |
| CRYPTREC暗号リストと危殆化 | 計算機の進歩で暗号は経年劣化する（危殆化）。国が「今使ってよい暗号」のリストを維持している |
| 鍵管理 | 生成・保管・更新・廃棄まで含めて鍵のライフサイクル。アルゴリズムが強くても鍵が漏れれば無意味 |
| ストレージ暗号化・ファイル暗号化 | 守るのは通信だけではない。保存データの暗号化は端末・媒体の盗難紛失への備え |

## 扱わない
- 共通鍵暗号方式・公開鍵暗号方式・ハイブリッド暗号方式 → L15（完成済み、参照のみ）
- ダイジェストに署名する使い方（デジタル署名） → L17
- デジタル証明書・PKI → L21
- TLSなど通信での利用 → L42
- 暗号化消去（CE） → L40

## 確認パート
- 通常クイズ2〜3問
- 出しどころ: 「ハッシュは復号できるか」（一方向性）／ダイジェスト一致から言えること（改ざん検知）／危殆化の意味
