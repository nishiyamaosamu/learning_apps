# SG-L58 データベースの基礎とセキュリティ

- **一言で**: 会社のデータは表で管理される — その表を「壊さない・漏らさない」機能ごと理解する
- **シラバス**: 中分類4「データベース方式」「データ操作」「トランザクション処理（同時実行制御）」「データベース応用」＋情報セキュリティ#5「データベースセキュリティ」
- **主担当**: なし（ログ管理の考え方は L37 が正。バックアップ方式は L59 が正）
- **依存**: L37 の後（ログの取得目的を既習として使う。強い依存ではない）

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| 関係データベースとDBMS | 行と列の表でデータを持ち、DBMSが管理する。保全機能・データ機密保護機能という言葉をここで |
| SQL | 表に問い合わせる言語、という位置づけだけ。SQLインジェクション（L8）が「この言語を悪用していた」と回収 |
| 同時実行制御（排他制御） | 2人が同時に同じデータを更新すると壊れる。先にロックする、を残高更新の例で |
| データベースセキュリティ | 暗号化・アクセス制御・ログの取得の3点セット。L36・L37の考え方をDBに適用するだけ、と接続 |
| データの活用先の地図（1シーン） | DWH・データマート・データレイク（R7問11の題材）・ビッグデータ。「業務のDB」と「分析のためのコピー」の区別だけつける |

## 扱わない
- メタデータ・データディクショナリ・分散ファイルシステム・データ重複の排除 → 暗記カード
- バックアップの方式・世代管理 → L59（次回予告として一言）
- SQLインジェクションの手口と対策 → L8・L46（完成済み/説明済み、参照のみ）
- データ分析・活用の流れ → L76（第8章）
