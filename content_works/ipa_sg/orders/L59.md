# SG-L59 バックアップ方式と世代管理

- **一言で**: 全部・差分・増分 — 取る時間と戻す時間のトレードオフを計算で体感する
- **シラバス**: 中分類4「トランザクション処理」のうち障害回復（バックアップの方式・世代管理・フル/差分/増分）
- **主担当**: ★ バックアップ方式（フル/差分/増分・世代管理・リストア時間計算）。L26・L35（説明済みの参照元）・L58・L84・L85が参照する
- **依存**: なし（第9章 L84・L85 より先に作る。復旧目標の用語（RTO/RPO）は L69 が主担当なので、この回では「目標の時間内に戻せるか」という言い方に留める）

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| フルバックアップ | 毎回全部を取る。取るのは遅いが、戻すのは1本で済む |
| 差分バックアップ | 前回のフル以降の変更を取る。戻すのはフル＋最新の差分の2本 |
| 増分バックアップ | 前回のバックアップ（種類を問わず）以降の変更だけ。取るのは最速、戻すのはフル＋増分を全部の最多本数 — 3方式を1枚の表で対比 |
| 世代管理 | 何世代残すか。直近だけだと「壊れたデータをバックアップしていた」に気づけない（ランサムウェア対策（L35）にも効く） |
| 取得サイクルと保存場所 | いつ取るか・どこに置くか。遠隔保管（L41）・3-2-1ルール（L35）をここで束ねる |
| 【計算ワーク】リストア時間 | R8問14の型を1問実演。「日曜フル＋毎日増分、木曜朝に障害」で何本を何時間かけて戻すか（反復ドリルは問題集） |

## 扱わない
- RTO・RPO・RLOの用語定義 → L69（第8章が主担当。この回は数字の計算だけで用語に踏み込まない）
- バックアップ運用の弱点探し・復旧判断のケース演習 → L84・L85（科目B）
- データベースの障害回復機能の内部 → L58（説明済み、参照のみ）
- WORM・バックアップの保護 → L35（説明済み、参照のみ）

## 確認パート
- 通常クイズ2〜3問（計算ワークとは別枠）
- 出しどころ: 3方式の「取る時間／戻す本数」の対比／世代管理が救う事故の型
