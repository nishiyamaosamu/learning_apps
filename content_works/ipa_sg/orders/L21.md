# SG-L21 PKIとデジタル証明書

- **一言で**: 「その公開鍵、本物？」に答える社会の仕組み — 認証局が身元を保証する
- **シラバス**: 情報セキュリティ#1「情報セキュリティ技術（公開鍵基盤）」全部
- **主担当**: ★ 証明書の仕組み（L42 が TLS の復習として参照。暗号方式の L15 と並ぶ第2章のもう一つの正）
- **依存**: L15・L17 の後（公開鍵ペアとデジタル署名を説明済みとして使う。証明書は「公開鍵に認証局が署名したもの」と説明するため L17 が必須）

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| 公開鍵の配布問題 | 公開鍵はだれでも配れる＝攻撃者も「本人のふり」で配れる。L15の仕組みに残った最後の穴、から始める |
| デジタル証明書（公開鍵証明書） | 認証局が「この公開鍵はこの持ち主のもの」とデジタル署名で保証した電子データ。運転免許証の例えで |
| 認証局と信頼の連鎖 | ルート証明書＝トラストアンカー（信頼の基点）から中間CAを経て個々の証明書へ。「知らない相手でも、信頼する発行元をたどれば信じられる」構造を図で |
| サーバ証明書・クライアント証明書 | サーバの実在を利用者に示す／利用者・端末をサーバに示す。向きの違いで対比 |
| CRL（証明書失効リスト） | 鍵の漏えいなどで有効期限内でも無効にできる。「証明書は見つけたら失効も確認する」まで |
| PKIという枠組み | 証明書・認証局・失効の仕組みぜんぶをまとめて支える基盤の名前、として最後に回収 |

## 扱わない
- 公開鍵暗号方式の仕組み → L15（完成済み、参照のみ）
- デジタル署名の仕組み → L17（参照のみ）
- HTTPSでのサーバ証明書の使われ方（TLSの流れ） → L42
- 電子署名法・認定認証事業者・電子証明書 → L52
- S/MIMEでの証明書利用 → L44

## 確認パート
- 通常クイズ2〜3問
- 出しどころ: 証明書が保証すること（公開鍵と持ち主の対応）／トラストアンカーはどれか／有効期限内に無効化する仕組み（CRL）
