# SG-L15 暗号方式

- **一言で**: 読めない形にして送る — 鍵が同じか・違うかで2方式、実際は両方のいいとこ取り
- **シラバス**: 情報セキュリティ#1「情報セキュリティ技術（暗号技術）」の前半（暗号方式そのもの。ハッシュ・鍵管理・CRYPTREC・危殆化はL16へ）
- **主担当**: ★ 暗号方式（L42がTLSの復習として参照。平文・暗号文・鍵の呼称はこの回が正で、L16〜L21・L42が前提にする）
- **依存**: なし（第2章の1本目。作り直しの際は narration/ipa_sg/sg-L15-encryption.md の呼称——「平文（ひらぶん）」の読み・音声と字幕の分離——を維持する）

## 扱う

| 用語・論点 | 何を語るか |
|---|---|
| なぜ暗号か | 通信は途中で盗み見られる（L11参照）。読めない形に変えてから送り、鍵を持つ相手だけが戻せる |
| 用語の整理：平文・暗号文・暗号化・復号・鍵 | 以降7本すべての土台になる呼称をここで固定する。「平文」は音声のみ「ひらぶん」と仮名書き |
| 共通鍵暗号方式（AES） | 送る側と受ける側が同じ鍵。速いが「鍵をどう安全に渡すか」が課題、まで |
| 公開鍵暗号方式（RSA） | 鍵はペアで作り、公開鍵で暗号化・秘密鍵で復号。鍵は配れるが処理は遅い |
| 鍵の数の対比 | 100人が互いに通信すると共通鍵は4,950本・公開鍵は100組。数字ドンで方式の使い分けを腹落ちさせる |
| ハイブリッド暗号方式 | 公開鍵で共通鍵を渡し、本文は共通鍵で暗号化。TLS（L42）がまさにこれ、と予告で締める |

## 扱わない
- ハッシュ関数・メッセージダイジェスト・CRYPTREC暗号リスト・危殆化・鍵管理・ストレージ/ファイル暗号化 → L16
- デジタル署名（鍵の使う向きが逆の応用）→ L17
- デジタル証明書・認証局（公開鍵の本人性の保証）→ L21
- TLS・HTTPSの流れ → L42

## 確認パート
- 通常クイズ2〜3問
- 出しどころ: 同じ鍵を使うのはどの方式か／公開鍵方式で復号に使う鍵（秘密鍵）／組み合わせ方式の名前
